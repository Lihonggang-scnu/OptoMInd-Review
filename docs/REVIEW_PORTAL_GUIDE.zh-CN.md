# OptoMind Review 评审测试入口

## 方案一：无需下载的云端成果回放

打开 <https://lihonggang-scnu.github.io/OptoMInd-Review/>。网页直接展示三组真实端到端研究，可以切换研究题目、查看核心指标、以 10× 速度播放运行事件、逐项打开十三个研究阶段，并核验中英文 PDF、引用映射、质量报告、结构审计和出版源文件。该模式不调用模型，不需要密钥，也不会重新执行研究。

## 方案二：下载源码后的统一前端

Windows 用户解压源码后双击仓库根目录的 `START_OPTOMIND.cmd`；Linux 或 macOS 用户执行 `./start_optomind.sh`。浏览器会打开 `http://127.0.0.1:8765/`，静态回放立即可用。

如需提交一个新问题进行真实测试，把项目方私发的 `api_keys` 文件夹放到仓库根目录，保持文件名不变。进入“真实提问”，点击“检查并准备真实运行”。程序会依次核对项目资产、密钥、Python 科研环境、Qwen 模型和学术文献服务；首次运行缺少依赖时会自动创建 `.venv` 并安装。全部检查通过后，问题输入框和运行按钮自动解锁。

“快速真实验证”保留问题理解、文献检索、证据组织、论点形成和成稿主链，跳过图像生成、翻译和 PDF 编译；“完整自主综述”沿用三组正式实验所使用的出版主链，包含全文统筹、双语出版和可视化处理。两种模式的产物都写入独立的 `local_runs` 目录，不会覆盖三组正式回放。

本地服务只监听回环地址，一次只运行一个任务。页面和日志不显示密钥内容；GitHub Pages 只包含已脱敏的精简事件记录与可公开最终成果，不包含真实密钥、下载论文缓存或本机完整运行目录。

## 可直接提供给评委的下载测试说明

如需验证系统能够接收新问题并开展真实综述研究，可从 [OptoMind-Review 项目源代码与三组正式成果](https://github.com/Lihonggang-scnu/OptoMInd-Review) 下载并解压项目。Windows 环境推荐安装 Python 3.11 或 3.12；如需完整模式生成中英文 PDF，还应安装能够提供 `xelatex` 和 `latexmk` 的 TeX Live 或 MiKTeX。随后将项目方私下提供的完整 `api_keys` 文件夹放到项目根目录，使最终路径为 `OptoMind-Review/api_keys`，再双击根目录中的 `START_OPTOMIND.cmd`。统一前端启动后，三组静态回放可立即使用；选择“真实提问”并点击“检查并准备真实运行”，程序将自动检查项目与回放资产、Python 科研依赖、Qwen 模型服务和学术文献服务，所有检查通过后才会解锁问题输入框。评委输入自然语言形式的综述研究问题后，可选择“快速真实验证”或“完整自主综述”：快速模式保留问题理解、文献检索、证据组织、论点形成和成稿主链，模型预算上限为 3 元，并跳过图像生成、中文翻译和 PDF 编译；完整模式使用与三组正式实验相同的出版主线，模型预算上限为 15 元，包含全文统筹、视觉处理、双语出版和 PDF 生成。运行时间受题目规模、网络、文献可得性、模型重试和本机出版环境影响，程序不承诺固定完成时间。新运行结果单独保存在本地 `local_runs` 目录，不会覆盖或改变随项目提供的三组正式运行记录。macOS 或 Linux 用户可在项目根目录执行 `python3 quickstart.py ui` 启动同一界面。

真实运行需要适配不同设备上的 Python、终端编码、端口、网络服务和 PDF 工具，纯前端启动在部分环境中可能无法一次完成全部准备。为提高现场测试的成功率，项目同时提供跨 Agent 操作 Skill、根目录 `AGENTS.md` 和中文说明书 `AGENT_GUIDE.zh-CN.md`。使用者可将解压后的项目目录交给具备终端能力的 Agent，由 Agent 按项目说明完成环境检查、启动、状态识别和故障定位，从而处理常见的路径、依赖、端口、密钥位置、网络和出版工具适配问题。

可直接向 Agent 提交：“请将当前仓库作为唯一工作目录，读取 `AGENTS.md` 并使用 `optomind-review-operator` Skill；先运行只读环境检查并报告结果，再启动统一前端。不要显示密钥内容，不要覆盖三组正式记录，也不要在我确认运行模式前启动付费研究。”
