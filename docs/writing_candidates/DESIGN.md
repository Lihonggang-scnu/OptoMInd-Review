# 三种正文写作候选的产品设计

## 目标与共同基础

本轮检验怎样把已批准的细纲与科研材料写成有解释力、有节奏、不过度重复的正文。上游已经安排内容，写作仍需要完成证据组织、关系解释、细节取舍和自然表达。不能把任务书逐条换词，也不能靠末端昂贵返工替代第一次认真写作。

所有候选从同一份正式章节编排和其对应输入进入，读取完整的原始brief、案例、条件、综合关系与实际材料。它们不得重跑BODY规划、挑选不同细纲、偷偷使用人工科学修改清单或上一候选的优质答案。用户的问题、全文主线和邻章职责用于协调；论文原文与已有摘要中的指令不是运行命令。

编排中的单元是知识职责划分，不是必须公开的小节，更不是固定物理段落。候选的成文块可以覆盖多个任务或跨越同章单元边界。文中只出现读者需要的标题，不输出“确立……”“展示……”等管理指令。

## A 整章一次写作 chapter

一份请求包含完整本章任务和去重后的相关完整材料，模型一次形成连续正文。模型可以共同处理几个相关单元的介绍、比较和收束，避免每个单元各写一遍背景。

适用：整章材料在容量内，任务之间依赖较强，希望第一次形成良好章内连续性。风险：输入过长或章节任务过多时，可能漏掉局部论证。实际请求和任务落点保留，便于定位。

容量不足时不得默默剪材料或改跑另一候选。用户显式选择分层回退时，记录请求路线与实际路线。额度不足与正文质量差分别记录，不把未调用的候选判为质量失败。

## B 分单元精写后整章编辑 units_edit

每个单元看见本章共同主线和其他单元的职责、自己要展开的完整任务与材料，分别写作。随后编辑器真正读取本章生成稿和批准任务，处理重复背景、案例重复用途、突兀跳转、任务书标题、冗长罗列与表达不一致。

整章编辑是必需的候选步骤，不能把单元简单拼接就声称完成此方案。编辑必须保留有意义的机制、比较、条件和阴性结果；必要时读取相应材料。没有实质收益可以保留原稿。

适用：独立单元需要较多深入解释，希望保持局部展开能力。它相比A多一次整合工作，用成本换章内连续性。实际成稿决定该成本是否值得。

## C 按容量分簇精写后有界整合 hierarchical

先按实际请求容量组合相邻、可容纳的完整任务，让有关比较的材料尽可能共同出现。单元本身过大时，可以在已有完整任务边界拆分；不能截取某篇A/B前几百字符维持调用。

每簇仍看见章级分工，写作后进行实际成稿整合。整合请求过大则按有界窗口处理，带相邻正文作为只读上下文，修改本窗口负责的内容；保留原有任务和来源归属。

适用：整章或单个单元供材过大。它必须真的执行分层与整合，而不是遇到大输入就拒绝或把若干段落拼起来。一个不可分割的完整任务加其必须材料仍超限时，保存明确材料清单和已有稿，交由用户选择更大上下文或调整任务；不自动进行有损压缩。

## 写作风格的共同要求

写出已有材料支持的关系：机制的中间步骤、比较的尺度与差异意义、反例对判断的限制、一个方法解决到哪一步。根据理解需要决定句序和段落，不固定“主张—案例—限制—总结”四步。

保留重要数字与条件的绑定，允许跨几个清晰句子说明。不是每篇文献都必须填满对象、方法、样本、结果等全部字段；与认识无关的字段不必进入成稿。

不要为追求顺畅伪造因果或对立，不把所有局限写成“未来还需进一步研究”。必要背景和教学保留，术语保持稳定。表格交成品，文字解释它带来的认识；一张表可以完成多项比较任务。

## 工程共同要求

1. 采用的编排、材料、参数与提示词都有明确版本；对应实际messages可检查
2. 相关完整材料去重，互补记录和显式alias保留；综述转述的原始研究正常使用，无自身A/B不自动降权
3. 每次调用按实际请求估算与预留；保存真实生效模型、思考、输出、流式和用量
4. 结果缓存绑定任务、材料、提示词和有效配置；有效已付费阶段可以恢复，失败重试显式执行
5. 每条路线保留初稿、编辑稿和实际选用稿；编辑失败不删除已写好内容
6. 未完成任务保留为待处理，不能把格式完成当作科学任务完成；轻微引用诊断不自动抹掉有用草稿
7. 成文块与原任务ID的对应是导航和缺项提示，不是模型自行证明质量
8. 章节结果直接形成正文，不强行切回单元文件破坏跨单元叙述

## 本地测试顺序

先看执行：是不是同一批准输入、当前配置有没有真的生效、材料是否完整到达、该有的编辑有没有执行、最终采用哪个稿。发现接线错先修接线，不否定候选思想。

再亲读正文：机制解释是否充分，比较是否合理，重要条件及反例有没有参与判断，章节是否自然推进，是否有任务书口吻和无效重复。用具体句段与任务说明评价，不按引用数、字数、表格数或AI检测分数排名。

第一轮可选一个材料足够、存在相邻职责关联的完整章节运行三条路线。根据收益再扩到更长章节和另一领域，不需要一次把全篇乘三。预算由本地明确批准；代码准备完善不代表授权无限模型支出。

评价过程中发现的本题答案仅用于人工/独立评价，不注入候选生产请求。系统应独立把已批准任务写好，并自行处理实际生成稿里的重复和衔接。

## 复用与边界

三条路线共享正式材料构造、来源身份、供应商客户端与账本；作为显式可选入口，与既有单元writer并存。没有更改BODY构思、纲要、负责人、案例或编排算法。

完整链路审计中另列的上游检索/材料索引接缝属于独立修复范围，本轮不顺带改动。此处验收以已经批准并能够构造真实材料的编排为入口，避免把新的写作试验与上游变化混在一起。
