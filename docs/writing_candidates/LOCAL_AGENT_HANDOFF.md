# 本地测试交接 先核对落实 再评价正文

## 背景与用户目标

OptoMind已经有经过反复修复和加强的细纲。本轮目标是让写作真正实现这些论证任务，减少独立单元直接拼接造成的啰嗦、重复和割裂，并形成准确、自然、有解释力的综述正文。用户要求质量优先，允许后续再找成本合适的组合；不能因为是第一轮测试就用简陋实现代表一个方案。

本轮三个候选的具体设计见DESIGN.md，运行参数与产物见README.md。它们属于可选写作入口，现有BODY规划和编排未改。不要重新跑规划，也不要再拿早期粗纲替换已经批准的细纲。

## 开始前选定输入

1. 锁定此次拉取的源码提交和所用配置文件
2. 明确一个已经批准的CHAPTER_ARRANGEMENT.json，以及它实际对应的ARRANGEMENT_INPUT.json。记录路径与哈希；不靠最新修改时间猜文件
3. 核对编排来源是采用后的完整章节，未选单元仍在。如果使用加强后的CURRENT_PLAN，先确认它指向的完整packet，再用正确编排与输入进入写作
4. 保留现有卡片、精读、补充材料与本地索引；本轮无需重复采集
5. 配好本地tokenizer路径，避免把UTF-8字节上界误认为实际token。预览不读取密钥、不发模型请求

## 先做三个预览

以Windows PowerShell为例，变量替换为本地真实批准路径：

```powershell
$py = 'python'
$arr = '已批准的CHAPTER_ARRANGEMENT.json'
$view = '对应的ARRANGEMENT_INPUT.json'
$tok = 'data/tokenizers/qwen3_5_9b/tokenizer.json'
$config = 'config/writer_candidates/quality.json'
$root = 'outputs/writer_candidates_local'
foreach ($route in @('chapter','units_edit','hierarchical')) {
  & $py scripts/upgrade3/writer_candidates.py --arrangement $arr --view $view --tokenizer $tok --route $route --config $config --output "$root/$route"
}
```

质量配置是Max写作与Max编辑；balanced.json是Plus写作与Plus编辑。第一轮优先选同一配置比较三种写作方式，随后对有用路线再降成本。不是要求每个配置与每条路线都跑遍。

预览中的后续编辑请求需要真实初稿才可构造，因此该阶段会明确标为尚待初稿，不要用预先伪造的编辑请求替代真实运行。

## 检查落实再付费

先看实际消息、材料清单与任务映射：

- A是否包含本章全部批准任务与相关完整材料，并允许跨单元组织正文
- B是否每个单元拥有共同章节分工、自己的完整材料，且随后真正调用编辑器
- C是否按完整任务/材料分簇，后续编辑是否有相邻正文语境；是否有某个完整原子任务仍超限
- 当前模型、思考、回答、stream和超时是否与配置一致
- 有无版本错配、来源别名未解、互补材料漏入、旧纲残留覆盖新任务
- 相同材料在同一请求中是否无意义重复；科学内容有没有被截断

有任何落实错误，先修复对应接缝再判方案。容量预检拦住不等于模型质量差；仅生成了初稿但编辑未完成，不得把它当作完整B或C参与最终排名。

## 真实调用与恢复

在用户批准本地预算之后，在预览命令后增加 --run --budget-ledger <同一个账本路径>；新账本还需要 --budget-limit <已批准总金额>。必要时用 --key-file 指向本地既有密钥文件，不上传密钥。

全部候选共用同一账本，每次按实际调用预留，不按假设所有未来阶段都执行来占满预算。先挑一个值得测试的章节；不默认整篇乘三，也不默认把质量和经济配置全部跑一遍。

重复相同命令会恢复兼容的成功阶段。失败、未知结算或不完整输出先检查落盘记录，再决定是否加 --retry-failed。不能为了重试删掉账本、raw或旧成果。

容量确实不够时，可以显式使用 --fallback-hierarchical，运行记录会同时保留请求路线和实际路线。比较时按实际路线解释结果，不把回退结果当成A的一次调用。

## 评价内容

先亲读生成稿，再使用独立模型辅助判断。评价者读到批准任务、相应材料及实际成稿；不把本地Agent自己先提出的科学修法发送给候选写作者或编辑器。

重点看：

- 机制与论证关系是否真正展开，还是仍然点名就算完成
- 研究比较是否保留对象、基准、条件与不同结果的意义
- 阴性结果、反例与必要背景是否保住
- 原单元交界处是否仍反复介绍、总结，案例重复是否有不同作用
- 标题和正文是否残留任务书口吻，是否每段都用同一模板
- 哪些段落有明确认识增量，哪些改动只是换词

任务ID映射只能帮助定位，不代表其科学内容已经完成；引用数量、篇幅和表格数量均不代替内容阅读。也无需为少量不影响理解的小误差无限返工。

## 回传资料

保存采用的输入/配置/源码SHA、阶段请求与返回、用量与费用、实际分簇与编辑范围、初稿和最终采用稿、恢复记录、实现核对与内容评价。对请求中不宜公开的论文原文和本地路径作明确标注与脱敏，保留原件哈希和定位；不要冒称脱敏视图是字节级请求。

回报时先说明各候选究竟完成了哪些阶段，再谈优劣、成本和下一步。局部失败不自动否定整个方案，执行正确后没有明显收益的复杂步骤也不必强行保留。
