# 本地Agent开工指令 写作候选 Plus优先 总预算60元

请接手OptoMind写作层的真实测试。先读取本文件、README.md、DESIGN.md和VERIFICATION.md，再检查实际代码、配置与预览请求。

## 背景和目标

上游细纲已经投入较多工作，写作需要把机制、比较、条件和案例写成真正连贯的论述。此次已有三套可直接运行的候选：整章一次写作、共享章级语境的分单元精写后统稿、按容量分簇精写后整合。不是让你重新规划正文，也不是拿简化临时脚本代替正式方案。

用户明确要求：质量优先，同时尽量用Plus解决；Max是最后底牌，不随意出动。评价先检查方案是否正确落实，再判断文本效果。接错输入、参数没生效、编辑没执行，不能算作方案失败。

## 范围与自主能力

- 复用已批准的完整章节编排、对应输入、A/B、精读与补充材料。不重跑上游，不重新检索全部论文
- 写作者、编辑器独立处理本轮任务。不得由你先列出本题科学错误或答案再交给模型修正
- 你的亲读与点评用于选择下一次试验、评价结果。调整链路只能写通用职责和接口修复，不把这个题目的结论写入生产提示词
- 保留原稿、候选稿、实际请求、原始返回、参数、费用和恢复记录。不得用早期粗纲替换当前已批准产物

## 预算

本轮所有新增外部付费模型调用共用 **60元人民币总上限**，包括写作、编辑、额外评价、失败后的明确重试及未确定费用的占额。不是每条路线60元，也不是要求必须花完。

保存启动时账本快照，沿用已有共享账本和历史记录；不要删旧账或清空占额来腾预算。以启动快照区分本轮新增费用。本轮上限不能因为旧余额或换配置而扩大。

首批尽量用10—15元以内建立可用判断，其余预算按收益分配。Max累计支出及未决占额建议最多占本轮10元，且只有下述升级条件满足后才动用；预留不足时停止该调用，交代还差什么，不偷偷降低材料完整性。最多使用60元不等于批准无限重试。在上述预算和升级条件内，由你自主安排正常调用，不必逐次向用户反复请示。

## 可选配置

1. balanced.json：默认，Plus写作＋Plus统稿；思考16,384、回答49,152
2. economy.json：Flash写作＋Plus统稿；两者均思考16,384、回答49,152
3. plus_reasoning.json：Plus全程，思考32,768、回答32,768；适合关系复杂、预期成稿篇幅适中的任务
4. selective_max.json：Plus写作＋Max统稿；仅在重要问题经Plus处理仍不理想时，对选中的困难范围使用
5. quality.json：全Max参考，保留而不常规启用。只有现有证据指向写作本身需要更强模型时，才考虑一个有界参考调用

Plus的合并输出容量上限为65,536，因此第三档是把空间更多分给思考，不是回答空间也增大。长篇幅任务优先保留第二类较大的回答空间。所有上限都不是要求凑满。

付费CLI可能使用Max时还需显式 --allow-max。没有自动升级；不得为了“配置名叫quality”就默认用全Max。

## 实施顺序

### 第一步 核对输入和执行方案

拉取本次锁定提交，记录HEAD。选一个已经批准、相邻单元之间存在比较或衔接关系的完整章节。三条路线先从相同批准输入预览，核对实际messages而非只看参数说明。

检查完整任务、source_brief_details、案例、条件、反例、argument_relations、来源用途、alias及互补材料是否到达；核对所用ARRANGEMENT_INPUT与编排版本。使用本地tokenizer，不把UTF-8字节上界当实际token。

检查实际模型、思考、回答、stream、超时、分簇和编辑阶段。路线A应一次整章写；B应真正统稿；C应保留完整任务和材料后分层整合。后续编辑请求必须根据实际初稿生成。

### 第二步 Plus先写好

优先用balanced跑A整章一次写作，亲读后决定第二笔钱：

- 若整体很好，只剩少量局部问题：不要为了凑齐组合跑所有候选。可用B验证局部展开优势，或选必要范围检验统稿是否真有增益
- 若整章有任务被压薄、段落展开不足：跑B，检查分单元精写加实际统稿能否改善
- 若实际上下文受限，或大输入明显影响组织：跑C。必要时可设置明确记录的工作上下文上限来分簇，保留完整材料；把质量分簇与供应商容量超限区分开

首轮不要直接全篇乘三。先找到值得继续的路线，再用另一个论述类型或另一章验证，不为追求严格控制变量花掉预算。

### 第三步 在Plus范围内优化性价比

根据实际结果，只选最有判别价值的一项：

- 关系复杂但成稿篇幅适中，比较plus_reasoning是否更会解释
- Plus成稿已经可用，试economy看Flash初稿＋Plus统稿能否保住质量而降本
- 某路线执行错误，先修通用接缝后重测受影响阶段，不重写全部已有好稿

不要把五档配置全部跑一轮。配置变更、提示词变更、素材变化都要记录，让结果能够归因到实际运行。

### 第四步 Max只作底牌

只有重要任务在Plus初稿和有根据的一次Plus改进后仍明显失败，且确认材料、任务和配置已经正确到达，才考虑Max。先判断失败点在哪里：

- 初稿有内容，主要败在跨段综合/重复/条件衔接：优先selective_max，把强模型花在统稿
- Plus初稿连关键关系都无法展开：才考虑全Max配置对一个有界范围给出参考

升级前在记录中写清：为什么值得、预期改善哪种通用能力、实际完整输入规模、费用预留和本轮余额。不得输入人工给出的本题科学答案。没有重要未解决问题时，Max支出可以是0元。

## 成果评价

先给出每条路线的落实核对，再亲读正文。少引用几篇不直接判漏写，句子长短也不是评分目标；重点是：

- 机制的中间关系是否真正展开
- 比较对象、条件及差异意义是否清楚
- 案例和反例有没有发挥细纲指定作用
- 原单元之间的重复、跳跃和任务书口吻是否减少
- 编辑有没有删掉有用知识，只留下顺滑空话
- 这次额外费用换来了多大阅读和理解收益

初稿与编辑稿分别评价。评审最好先遮去模型/路线标签，避免名字带来的偏好；不必搭建复杂盲评系统。你的点评不可作为下一候选的必答科学清单。
