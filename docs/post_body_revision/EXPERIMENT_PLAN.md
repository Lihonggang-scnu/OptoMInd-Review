# A B C 修订方案的小额实验

## 目标与当前状态

代码为三个可运行候选方案，不是三个已经验证有效的质量方案。目标是以最小必要改动解决真实问题，保住已有知识，并观察费用和质量之间的取舍。程序通过测试只能证明输入、状态、补丁和恢复处理；科学判断由本地独立 Agent 阅读实际输出和证据完成。

不重跑上游，不把旧稿引用数量或删字数当目标，不围绕某篇文章写专用答案。

## 共同控制

每个 case 固定 BODY 字节、研究问题、实际范围、最终细纲、材料与论文身份。A/B/C 使用同一 case 文件；模型配置、提示词、费用和运行指纹分别落盘。正文来源必须明确，不能把已知错误缓存文字说成修后生成。

先使用默认同模型的 A/B；C 只在实现规定的失败边界升级。不同时改变提示词、材料池、章节组织和模型，以免无法归因。新增材料应生成新的 case/输出目录，不能继续比较成同一轮。

## 第一步 离线确认能直接测试

1. 运行专项测试与三个录制样例。A/B/C 的单问题边界应分别可走到 2/3/5 次回调（C 使用拒绝后升级的专用录制）。
2. 检查 baseline 不改写、候选补丁范围、未决状态、调用/恢复记录；修改输入后的 resume 必须拒绝。
3. 从实际 BODY+PLAN 准备 case，再对 A/B/C preview。亲读准备出的全文主张、章级 thesis、段落任务和少量材料，不能只看材料数量。
4. 预览只证明输入合同和大小适配，不代表模型读懂。若历史 source 标签与稳定身份/实际内容冲突，先保留未决，不给它伪造正确答案。

## 第二步 固定问题 比较修复能力

从已有真实材料中挑一个有代表性的局部任务集合。可在 case 的 `known_fixed_issues` 提供共同的问题合同，直接使用该正文版本的 block ID 和逐字原文。B/C 不再付费重新发现同一组问题；A 仍用合并调用产生补丁，但不能变换所给问题身份和顺序。它们都允许判断问题不成立。

这里的“固定问题”不等于人工金标准。可由本地独立 Agent 对照证据提出并复核，记录其依据和不确定性；不要把待核实观点写成一定要达到的结论。

优先覆盖：

- 一个确有条件/归属/数值问题的局部表述
- 一个同用途实质重复或程序性套话问题
- 一个容易被误删的有效内容：必要理论、机制、阴性结果、范围条件或合理呼应

避免同一段同时交给多项补丁争用。确需跨段统一时，这版会保留冲突/大范围任务为未决，不用拆开改几次绕过保护。

固定问题这一层主要比较“能否修对并保持好内容”，不把问题发现差异混进来。B/C 在此模式省去了发现调用，因此费用不能代替端到端自主审稿费用。A 在合并阶段看到导航而非完整证据，B/C 作者会读取完整选中材料；这属于方案本身的信息使用差异，不能把结果只归因于调用拆分。若要纯粹检验模型/提示词，应另行固定其可见材料，不同时变动多项。

## 第三步 自主审稿与跨领域留出

完成固定问题检查后，去掉 known_fixed_issues，用同一正文让 A/B/C 自主发现问题。比较误报、真正改善、遗漏与副作用，而不是谁提出的意见多。

为避免只适配当前题目，在已有资产中补选两个不同领域、不同文章用途的 case。例如一个包含理论/方法教学，一个偏技术路线或系统比较。具体题目由本地现有材料决定，不向生产提示词加入学科专用答案。

至少有一个题目在调提示词时不使用，作为留出检查。必须包含本来正确且充分的段落，检验模型能否“不改”。若其他领域只有细纲而没有正文，只能检查准备/职责理解，不能声称验证了文章修改质量。缺资产就记录缺失，不为了形式完整重新跑全链。

这不是全组合搜索：先默认 A/B/C 各一组，只对暴露出的单一变量做一次有理由的复查。不要把所有模型、温度、思考预算、提示词、材料组合笛卡尔积展开。

## 本地 Agent 替代人工主观评分

使用 evaluator 产生的盲评包。在新上下文中评判，不看方案名、模型、费用、生成过程和另一评估者的回答。读取实际原文/候选及相关材料，不依据修改说明或 changed=true 判好。

输出必须说明：哪个问题改善了、哪段产生了回归、哪些知识保住或丢失、还有哪些问题不能判断；科学判断必须有包内证据 ID。程序校验引用与文本定位，但不能证明 Agent 的科学判断必然正确。

对一小部分包交换左右顺序复评。若偏好或保留判断冲突，结果标记不确定；不是不断调用直到喜欢的方案获胜。必要时只对一个高价值争议请求另一个独立 Agent 复核，并把额外评价费用单列。

无需用户逐篇手工评分，但保留无法判定/需要补证据的状态。Agent 评价不是人工金标准；同一个模型的生成、核验与盲评仍可能共享偏差。

## 成本与结果

记录实际 provider usage、按配置规则计算的费用、已知小计、未知占额与耗时。共同预算账本覆盖三个方案。评价 Agent 的成本单独记录；未取得费用数据就留空，不默认免费。

输出分开看：

- 相对 baseline 的有依据改善/不变/退化/不确定
- Agent 指认的解决项、剩余项和新增错误，按严重性记录
- 有用知识和条件是否保留
- 程序补丁、引用身份、恢复和未触及字节检查
- 生成费用与耗时，以及另计的评价成本

前沿计算只是当前 case 的描述性筛选。严重回归、重大知识损失、缺评价、换序分歧、费用不明或录制样例均不进入合格前沿。不存在一个通用总分能替代这些关系，也不保证一次小样本结果就是跨领域最优。

## 停止条件

- 预算不足、输入超限、材料不足、身份冲突：停止对应调用/任务，保留原稿和原因，不自动加钱、截断或猜来源
- 一个问题只有一次基本修订；C 满足条件时最多一次升级作者与核验。失败后保留未决，不继续循环
- 发现反复删除关键知识或制造严重新错误：停止该配置的扩大实验，先分析实际输入与返回
- 获得一组质量与成本都清楚的可比结果后先汇报，不自行修改上游、重跑完整 BODY 或宣布投稿就绪

## 回报内容

提交实际源码 SHA、case/正文/材料哈希、配置、运行和恢复条件、A/B/C 输出、独立评价及解盲报告、账本摘要、失败记录。公开前区分项目生成文字与论文原文，不上传密钥、权利不明全文、数据库或含原文的完整请求。缺失原件保留定位和哈希。
