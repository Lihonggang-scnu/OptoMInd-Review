# 给本地 Agent 的启动说明

请在独立本地工作区测试本分支。源码位置与云端验证见 PUBLICATION.json 和 records/。你负责真实实验与独立质量判断，本轮不需要用户逐项人工评分；不能因此把模型评判叫作科学真值。

1. 核对源码和 README。先运行专项离线测试及 A/B/C 录制样例，确认三个方案都是可执行路径，C 确实经过拒绝后的一次升级。不要将模拟正文当质量成果。
2. 固定当前验收过的 BODY 和相应最终细纲、材料。用 prepare 生成自包含 case，检查全文主张、章级职责、原段落任务、材料身份及少量实际内容。已知旧缓存错误不自动成为事实。
3. A/B/C 分别 preview。超限或材料格式冲突先看诊断；不删掉有用材料凑合过关，不修改上游。已有显式材料清单可以接入，不需要编写新适配器；不能识别的输入先记录。
4. 真实调用前取得并固定本轮总预算。用同一 shared_budget.sqlite，三个方案保持同一 case。默认顺序运行；即使你选择并行，也必须是不同方案目录且同一预算账本。不得读、打印或上传 key 内容。
5. 第一轮先做固定问题的小范围对照，再根据结果决定是否自主审稿/增加留出题目。按 EXPERIMENT_PLAN.md 执行，不展开参数全组合，不重跑 BODY。
6. 运行 evaluate prepare，创建随机左右顺序的盲评包。为各包启动独立的新上下文评估 Agent，只给 guide、schema、该包及必要材料读取权限，不给 decode_key、方案名、费用或生成器自评。让它实际对照文本和材料后写 judgments JSON；不要让程序或模型填一个预设“通过”。有疑问可返回不确定。
7. 用 evaluate report --output 保存 UTF-8 结果。检查无效/缺失判断和换序分歧；由你结合所有已完成结果给出有依据的推荐。代码计算的前沿是辅助，不是通用质量认证。
8. 保留运行参数、完整 SHA、baseline/candidate/调用/评价哈希、账本、失败与未决事项。先交付报告，不自动合并、替换正式稿、进入首尾生成或扩大上游实验。

三个模型客户端配置目前使用现有仓库支持的 Qwen 型号；本地编程 Agent 可承担盲评，不要求再通过 API 付费调用评估模型。若另用 API 评估，需单独授权预算并记录成本。无论哪种方式，都应由未参与该候选生成的新上下文评估。

必要的实际入口命令、fixture 路径、输出布局见 README，判据和停止条件见 EXPERIMENT_PLAN。所有真实请求和科学材料默认只留本地，公开内容先审查权利与敏感信息。
