# PDF 自动解析、识别与并行验收（2026-10-13）

采用原生 JATS/TEI 优先、PDF 本地 Docling 全页布局＋原图裁切＋`qwen3.5-plus` 公式/表格定点识别。**本机运行档采用 Docling 2 进程、整个批次区域并发 8**，由显式 CLI 参数启用。通用类默认仍为保守的 1＋4；不能把初始值当作所有机器的最快设置。正文、规划、首尾生成算法未在本轮修改。

## 实际结果与采用理由

五篇完整 PDF，共78页，包含论文、跨领域格式差异的综述及补充材料。Docling 2.138.0 使用本机 RTX3080 10GB 和离线模型。

| 峰值设备显存 | 3,354MiB / 4,851MiB |
| 两档本地内容比较 | 页、区域、公式、表、文本及601个本地表格单元格一致 |

本地双进程收益明确。12路区域识别比8路只快约3秒；单篇任务已被大表的输出时间主导。采用2＋8作为吞吐与稳定性的运行档，不继续无限加并发。

8路批次运行期间另有一次9个未发送区域的恢复检查短暂重叠；表中费用按原始响应的request_id逐项关联账本，不使用包含其他调用的全局前后差。完整原始收据保留，`PARALLEL_SUMMARY.json`同时列出两个口径。批量识别使用已缓存的Docling布局，上表不能解读为全新下载、全新本地解析与识别合计40秒。

## 内容亲审与剩余缺口

根智能体亲读真实返回并对照原截图：带宽界的式(6)/(12)分式、根号和变量关系保留；密集表28行11列的主要数值、括号内限值和混合单位保留。8路表中的一处设计标签下标遗漏已记录，未手改模型响应。此前五篇完整供材、便宜OCR候选、转换器和无损元数据去重验收见保留的`ROOT_REVIEW.md`、`ALL_MODEL_RESULTS.json`、`CONVERTERS.md`。

批次8路和12路都留下两个明确缺口：一处参考文献区域被本地布局误判为公式，模型报告并非公式；一张复杂比较表分别返回了不合合同的列对象、截断JSON。程序保留原图、本地候选和失败响应，不把这些标成已识别。12路这一轮截断更多，未获得足以推广的额外质量收益。之前已经接受的该表缓存仍可免费复用；本轮没有为追逐零错误重抽全部区域。

科学图像本轮只保存区域、图注和回看定位，不自动解读曲线或从图像推导科学结论。一次初始Docling单进程模型加载崩溃及其成功重试记录也保留在`DOCLING_SPEED.json`。

## 本轮接缝修复

- 共享实例约束整个批次；外层网络线程不会将每篇区域并发相乘。Docling槽在HTTP前释放。
- HTTP请求重叠执行，双账本的reserve/settle及共享tokenizer状态串行保护。账户拒绝、预算拒绝或未知费用立即阻止未发送工作，已发送工作完成落盘。
- 预算拒绝且确认尚未发送的区域可在下次恢复重新reserve；已成功区域免费复用。未知费用不自动释放、不自动重试。
- 识别尚未完成的批次checkpoint不再冒充完成缓存，无需手动改响应或填完成状态。
- 实际科学记录及条件完整进入普通阅读、A/B、practical/legacy定向阅读与独立M4；Docling表公共定位字段做可逆合并，不裁剪单元格内容。六表逐字段恢复比较见`ROOT_PROJECTION_CHECK.json`，实际消费者见`CONSUMER_SEAM_CHECK.json`。
