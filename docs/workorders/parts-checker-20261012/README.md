## 两项任务如何合起来

```text
正式选用的 BODY 句柄稿及匹配的上下文/材料
  → 后置职责构思
  → 结语 → 引言 → 摘要、关键词和题名
  → 03 完整句柄稿
  → 新校验员通读 → JSON 局部编辑 → 本地执行 → 有界失败反馈
  → 显式 selected_manuscript
  → 04 最终图表/引用映射与读者稿
  → 05 Markdown、TeX、PDF
```

原 BODY 写作与既有 BODY 全文编辑保持当前主线路。新校验员不是再跑一次旧 BODY 编辑，也不接管首尾构思或重写全文。两项新增能力都必须走正常入口，不依赖临时手填完成状态或手动选择产物。

## 材料与证据说明

- `research/parts/` 来自用户交来的 **43 篇**研究资料包及候选提示词，是这一轮新研究，不应与仓内较早的 35 篇指南混为一谈。它包含研究者的原文阅读记录、来源链接及分析，不包含论文全文。本地已读综合报告、接入说明、三套候选提示词，并对照代表性深读；没有重新逐篇下载 43 篇原论文。
- `research/editing/` 来自本轮编辑执行选型报告、审计和候选报告。外部项目的小测试、源码抽取、黑盒演示是研究证据，不是已经接入 OptoMind 的功能。
- DOCX 的纯文本正文另存供云端阅读；原 DOCX、执行器源码快照及完整研究演示仍保留在用户本机原目录。报告内锁定 SHA 链接可用于核对外部源码；不需要把四套完整平台装进本项目。
- 现有 03 装配保持 BODY；新校验员可以执行有依据的 BODY 局部修改。因此后者需要独立差分记录，不能沿用 `body_preserved=true` 表示整条链路从未改动 BODY。
