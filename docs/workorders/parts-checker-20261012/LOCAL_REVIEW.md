# 本地阅读判断与实施取舍

2026-10-12，阅读和工单整理；生产代码未改。

## 首尾研究

最值得采用的是具体起草动作：先从实际正文选择一条问题线，解释已有路径及其边界，再说明文章如何连接知识；摘要给出认识内容，结语组织认识之间的关系。当前 `_DUTIES` 太简略，候选提示词有直接可接入的位置，不需要另造首尾模块。

候选中按段推进的示范有帮助，但不能变成跨领域统一模板。导航本身合理，纯报目录才是问题；中心认识一致也合理，摘要与结语用途没有区别才是问题。引言的事实判断应有对应来源，作者自己的组织选择不需凑引用。

这批是新交来的43篇研究；与已有35篇指南分开标记。原研究作者完成的阅读范围见资料包，本地阅读了综合报告、三份候选提示词及说明，核对代表性深读，没有重新逐篇获取43篇论文。

## 编辑执行研究

赞成选型报告的核心结论：保留旧/新/理由 JSON，复用本仓的严格块定位底座，比接进一个完整编程 Agent 平台更贴合当前需要。Aider 的失败反馈、OpenHands 的回读及原子写入思路可以借鉴，外部默认的首匹配或容错定位不应直接用于本稿。

报告也纠正了几个实际接口判断：旧 `target_block_id` 没有参与定位；替换函数没有一般幂等性；已有严格执行器没有新的失败反馈闭环；顺序块ID不能跨快照直接复用。新模块要补这些接缝，而不是换一个 JSON 名称便宣称问题解决。

需要调整报告建议中的一个范围：用户不只要表面措辞校对，也举了公式和明确前后矛盾。不能把所有数字、引用或含义变化都推成待办。应允许由当前稿及提供材料支持的局部修正，依据不足再待办；既不自动模糊替换，也不追加一整套昂贵科学审稿平台。

两次逻辑调用总计是本地建议的默认实现口径，不是研究已经验证的模型轮数效果。最重要的是失败轮只修定位/执行失败项、保留成功项，剩余问题停止追改并随稿报告。

## 接缝优先级

1. 首尾模块仍只装配自己的区域，BODY 不改。
2. 新校验员处理实际03完整句柄稿，可以产生有记录的局部 BODY 差分。
3. 04消费校验员明确选中的稿件，05消费04读者稿。新入口与独立交付用法必须共用这一选择，不能一条路改了、另一条仍读旧03。
4. 程序执行成功只说明补丁落在指定原文；本地真实验收再判断自主发现及修改是否值得。云端先交出可运行接口、实际消息及离线短链证据。

本轮没有重新运行供应方的外部探针、没有生成新首尾、没有实现校验员、没有调用项目付费模型。研究证据保留为原作者记录，工单中列的是待实施验收。
