# 任务二：完整稿校验员与精确编辑执行

## 目标与定位

阅读全文（题名、摘要、关键词、引言、BODY、结语及已有图表），自主发现常见一致性和格式问题，输出严格的局部编辑 JSON，由本地程序精确应用。它不是第二个全文作者，也不是全面科学审稿系统。

位置为 **03 首尾装配成功后、04 最终编号前**。保留 BODY 现有全文编辑，不原样重复调用旧编辑 stage。首轮建议默认启用新阶段，同时提供显式关闭开关；沿用现有预算受控 Qwen provider，模型与容量可配置，不另建资金池或自动升级模型。

## 通读时检查五类问题

1. **术语、缩写、符号和单位的一致性**：不必要的重复展开、同一对象命名漂移、大小写及单位写法。摘要是独立可读部分，正文首次定义也可能必要；不能全局删除所有重复全称。
2. **标题、段落、图表、引用和交叉引用的结构表达**：标题层级或任务书口吻、残留占位符、表图说明与正文称呼不一致、错误交叉指代。来源身份由现有目录管理，最终数字由后续编号器产生。
3. **公式及数值表达**：公式界定符、变量/符号和文本定义不一致、明确的数值或单位表达问题。修正确有依据的错误，不自行重算缺资料的结果。
4. **局部前后矛盾与指代**：同一研究/对象/时间窗在稿内有明确冲突，或摘要、引言与 BODY 的承诺不一致。先区分合理的条件差异；依据不足时留下具体待办。
5. **表达和无新增作用的重复**：明显病句、重复句和重复说明。保留独立解释、有效比较、必要背景和阴性结果，不能把稿件机械压短。

以上是大方向，模型需从本轮全文自主发现具体问题。不得发送当前测试稿的人工科学错误清单、预制正确句子或上轮修改答案；不继承旧编辑器“通常不超过10处”的配额。

## 复用底座，补薄协调层

首选复用 `post_body_revision_contracts.py` 中的快照、分块、`normalize_case / resolve_target / validate_patch / apply_patches`。先核对函数前置条件，再适配外层 JSON。不要迁入整套 Aider/Cline/Codex/OpenHands，也不要再造第四个匹配器。

可借鉴 Aider 的失败块、相近实际原文、已成功无需重发等反馈组织，以及 OpenHands 的回读和原子落盘思路。相似搜索只找候选，最终仍须复制真实原文并严格唯一匹配，不允许阈值自动授权科学文本替换。

现有 `article_text_editor` 的 `target_block_id` 只记日志，全文搜索和120字符日志不能直接满足本任务。现有 contracts 是整批拒绝重叠，需要薄协调层先分离失败/冲突项，再将独立 accepted 子集交给原子 applier；不要采用列表先到先得。

## 模型与程序的最小合同

建议沿用核心字段，根层增加可信快照标识：

```json
{
  "snapshot_id": "程序给出的原稿SHA256",
  "changes": [
    {
      "target_block_id": "程序给出的块ID",
      "operation": "replace",
      "original_text": "从该块逐字复制的旧片段",
      "replacement_text": "完整的新片段",
      "reason": "结合当前上下文说明修改理由"
    }
  ],
  "unresolved_questions": []
}
```

允许 `replace/remove`，删除时新片段为空；不接受路径、新文件或整篇改写。首轮 `edit_id` 由程序分配，修复轮必须返回对应 pending ID。模型不制造 offset 或哈希。原 parser 丢弃根层扩展字段时，wrapper 应先验证和保存 `snapshot_id`，不能解析后再猜版本。

程序只向模型发送一次完整稿的带块标识视图，附职责标签、身份目录和必要材料；块标签不写进论文。不要“整稿一份＋完整块原文又一份”无意义双发。

## 执行和最多两次逻辑调用

建议明确采用 `max_model_rounds=2`：首次通读检查一次，失败项修复最多一次。没有失败就不发第二次。格式修复也消耗这个修复机会；物理传输重试另按现有费用/尝试记录，不用改输出目录重置轮数。这里是本地对用户“最多两轮”的具体建议，不应描述成原代码已有能力。

1. 保存 S0 原稿、字节哈希、请求/配置身份和完整响应。基于同一未规范化字符串建立块及原始区间。
2. 全部提案先在 S0 定位。目标必须在指定块内唯一命中；同块多处应扩大真实锚点，不能取第一处。批内禁止后一个提案搜索前一个提案生成的新文字。
3. 重叠的所有成员转 pending；明显互相依赖的多块修改先挂起。其余独立且有效项组成 accepted 子集，一次原子应用成 S1，保留完整 old/new/reason 和执行收据。
4. 第二轮回读 S1 的实际全文/必要完整上下文，携带 pending ID、原提案、失败类型、命中次数、候选原文及已成功项收据。只修失败项，不要求模型重新找一轮问题或重写全文。
5. S1 重新建立块 ID 和绑定。`B0001` 等是快照内顺序ID，插段后可能改变，不能把 S0 旧号直接换上 S1 的哈希继续用。未触及目标可用可信区间位移迁移；不唯一时回读实际候选，不猜。
6. 到上限保留成功成果和未决项。完整稿可带诊断继续交付；真正缺文件、版本不符或结构损坏才阻断。失败不能被静默冒充已经成功。

跨段联动超出现有单块合同的，首版保留待办即可；不要为了少见情况移植整套 scoped 科学修订系统。每个自动应用的提案须能局部独立成立。

## 应保护什么，不能保护过头什么

- UTF-8 原字节计算快照；在同一原文字符区间上执行，原子写候选。未修改区域、CRLF、Markdown 硬换行及管理标记保持原样，不以全半角或数学减号折叠提高命中率。
- 快照、块、原文绑定、唯一性和重叠由程序保证。执行收据记录输入/输出哈希及已应用 ID；同一请求恢复返回已保存结果，不能因新文字在别处出现就判 `already_applied`。
- 检查完整受影响段落/表格/公式的结构及引用，不只检查替换片段。编辑可能正好落在引用 token 内部，局部字符串解析会漏掉破坏。
- **不要把所有数字、引文或事实含义变化一律禁止。** 单位/数字格式、明确稿内矛盾、具有所给材料依据的局部公式或引用纠正属于用户需求；用最小适配携带依据，通过现有相应合同验证。缺依据的才待办，不为此加新审稿模型或逐条检索。
- 不把这些修改全部伪装成 `editorial`。现有 editorial 数字集合检查允许改符号、次序或删除，不能当事实保护证明。实施者应区分纯格式与有依据的含义修正，选用/有界调整现有验证接口，不搬入整套历史审稿流程。
- 来源目录不由校验员改写。局部引文有依据时可改成目录内真实句柄，记录身份变化并让04重新编号；不能凭空造论文、全局替换相似P号或手写最终数字编号。
- 模型可以对当前稿与提供材料足以确认的问题直接给修正；材料不足时具体说明缺什么。不要把校验员做成只会报风险的空壳。

## selected_manuscript 与消费者交接

建议返回明确的 `selected_manuscript`（path、sha256、status、provenance）及 applied/pending/diagnostics。字段名可调整，消费关系不可含糊：

- `no_change` 明确选原稿；部分成功选有效候选并附诊断。不要 glob 最新文件、静默退回03或借用 BODY 的 `selected_body` 混淆层级。
- `review_delivery.py` 在03成功后调用新 stage，04的编号投影只读取该 stage 实际返回路径；05仍只读04的 reader，元数据也从该文本产生。
- 同时覆盖独立首尾后的实际交付方式。现有归档 `run_final_delivery.py` 是另一条直接调用04/05的证据路径；提供调用共同生产函数的新入口/示例，不改写历史脚本和旧结果伪装新测试。
- 校验报告和选用来源要进入最终协调报告/明确sidecar。当前 publisher 不会自动继承这些字段，需显式接上。
- 04后插入的图注尚未包含在03正文里；有此类输入时，校验员应看到待插图注及图表资料，04后做确定性映射检查。不为此重排整条图表链，也不声称读过未提供的图注。

## 少量有判别力的离线验收

1. 同句出现在两个块，只修改指定块；同块多次和重叠出现不取第一处。
2. 一个成功、一个失配：第二轮看到 S1，保留成功项，只修 pending ID。含插段的例子验证块号迁移。
3. 冲突项全部挂起，独立成功项保留；旧快照响应不能应用到新稿。
4. 原始响应保存后恢复，不再调用模型；前缀型替换重启不重复追加，无收据不猜已应用。
5. CRLF、中文、数学负号、表格竖线、引用 token 内部修改和所有权标记有实际前后字节/结构对照。
6. 能执行有明确依据的格式或局部引用修正；不明依据留待办。至少一个异领域合成例子，不能只有本题语料。
7. 无修改时正式下游选原稿；摘要一处可见局部修改贯穿04 reader、05元数据及出版稿，证明没有拿旧路径。
8. 关闭开关不启动新阶段；已完成并附诊断可交付，缺选中稿/哈希不符确实停止；默认不开额外审稿或模型升级。

不以测试条数代替验收。保存实际 fixture 消息、响应、候选和最终消费者路径，云端免费验证逻辑；本地再测试自主发现能力、实际修改质量、命中率和调用成本。

## 交付

独立提交新 stage、薄适配、必要配置/CLI接线与测试，提供一条可由本地预算受控 provider 运行的正式入口。文档给出启用、关闭、同目录恢复和显式失败重试方式。未解决项列具体影响与建议，不把工作扩大成新科学审稿架构；不新增付费实验、不手写论文答案。
