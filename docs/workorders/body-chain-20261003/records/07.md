## Reproduced failures and actual changes

### A. Answered need still presented as unanswered

A real directed reader/store result satisfied the first synthetic task. Retrieval state was answered and `still_missing` empty, but the final tool material fell back to the pre-reading local question and sent that false gap to the owner. This could mislead later selection and revision despite a correct completion status.

The fix distinguishes an absent key from an explicitly empty current value. The reading-chain evidence retains before/after values, current useful content, owner input, cache reuse and real partial limit. No historical artifact is rewritten; reassembly through the adapter uses corrected semantics. Previously frozen downstream packets are not silently migrated.

### B. Pending assembly could enter downstream editing

Real one-unit history assembly correctly preserved prose and recorded a missing table or length truncation. It still had `status=complete` because every selected unit loaded, while `problems_resolved=false`. Delivery checked the file, entered editing and could continue with supplied stage fixtures.

After the fix, unresolved task/partial/restricted/error states stop before editing with `halt_reasons=["assembly_pending"]`. Existing unit/manuscript bytes remain untouched. A stale draft cannot override a current missing/failed arrangement report. Normal complete batches follow the previous path.

See [gate record](body07/delivery/README.md), [before](body07/delivery/BEFORE.json), [after](body07/delivery/AFTER.json), and failure-first log. An independent probe established that bare unmapped source-column handles are not repaired by the later bracket scanner; these remain blocking. Bracketed unknown identities alone retain their existing explicit-catalog path and its own later status checks.
