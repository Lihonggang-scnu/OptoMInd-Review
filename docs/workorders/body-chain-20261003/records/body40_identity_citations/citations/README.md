# BODY40 numeric citation consumption repair

## What was reproduced

`replay.py` imports the archived baseline runtime from `e0615b0` and current runtime, then calls both with the saved real Ch6_U4 / Ch7_U02 raw responses via a deterministic offline client. It does not regenerate model output, call a model/search service, rewrite archived inputs, or run a full BODY production chain. Derived before/after Markdown is saved separately here.

- Ch6_U4 baseline converts exactly one occurrence: `[11]` to `[P0011]`; the other eleven numeric identities remain unresolved
- Current Ch6_U4 retains the parsed raw body exactly, all twelve numeric identities unresolved, with no conversion
- Ch7_U02 retains its raw body exactly; all five `[Q01]` occurrences remain, with one deduplicated unresolved identifier diagnostic. Input evidence is a structured `question_id` within JSON-encoded chapter tool material, not a guessed identifier prefix
- Actual messages generated by baseline/current code are equal for each replay. Prompts and message payload builders are unchanged
- Source paths/hashes, before/after body hashes, repair records and diagnostic fields are in `REAL_REPLAY_BEFORE_AFTER.json`

## Bounded policy

Generated P-handle suffix aliases remain in existing inputs for compatibility, but do not establish the returned model's numbering dialect. Caller-supplied mappings retain precedence, including explicit empty maps and caller-confirmed partial maps; unmarked caller payload maps are still supported, now reported as caller-explicit. The consumer never trusts a mapping returned by the model.

Automatic bibliography mapping requires complete, unambiguous full-title evidence for the numeric body. A number with any unknown or conflicting bibliography definition is not uniquely resolved. Repeated identical definitions remain valid. Partial title evidence cannot be mixed with generated suffix aliases, and ambiguous title evidence conservatively prevents automatic conversion of the body. This is lexical matching of local titles, not DOI validation: title normalization preserves scientific symbols and only normalizes NFC Unicode, case and whitespace.

Input `question_id`, `question_ids`, `tool_call_id`, `tool_id` and `request_id` values in material containers establish known non-source identifiers. Plain prose and the model response do not establish IDs. Unknown bracket labels, code and links are not blanket-rejected. No identifier is guessed into a paper handle. Existing unknown P-handle and unresolved numeric diagnostics remain.

Run results, UNIT_RESULT and completion reports retain numeric repair provenance, input map origin, title map, unresolved mapping reasons and known-tool diagnostics. Unresolved reasons are also citation problems; successful conversions are records, not unresolved problems. CLI/assembly propagation is covered by the sibling implementation and tests.
