## 修复范围

### A. 初次 A/B 及旧材料刷新

初次章节细化复用现成的身份感知本地材料构造器，而不绕过它直接读卡片。明确不匹配的卡片内容不再出现在另一篇论文标题下。刷新旧记录时清理该不兼容卡片通道，保留诊断；已更正但缺少 A/B 的稀疏卡片也不能使历史坏内容复活。兼容的独立精读等材料仍可保留。

这是对明确矛盾的处置，不是要求所有旧卡片补全身份，也不要求综述转述原始研究拥有自身 A/B 或全文。

### B. 历史精读与真实下层缓存

免读必须同时考虑当前阅读任务、明确来源身份和实际可读内容。源材料指 practical reader 实际消费的正文及参考文献，不是目录名、snapshot 标签或时间戳。

检查覆盖 prior loader、适配器、adaptive journal/need 和真实 reader/store：若只改适配器，下层旧的空 source_hash 任务仍可能回放过期结果。使用既有 store 的内容绑定任务能力；变化后的内容/参考文献进入独立任务和输出位置，同一论文不额外占用独立论文名额。同内容搬目录保持复用。

旧 practical 结果可通过已有 PROMPT 内容证明兼容，无需改写旧文件或重新调用。缺少可核实内容证明不能冒充新任务已满足；可用历史材料按其兼容边界保留。明确外国论文身份的旧答案不能通过“历史保留”混回当前材料；同身份但源内容已更正的旧结果也不能作为新源的活动答案重新混入。

仅为本次指定的定向论文做内容检查，不把全池每篇全文重新读取一遍。没有新增自动付费循环。

### C. 首次案例精读进入正式下游

案例选择和附加使用同一个身份感知材料解析路径：选择看有界投影，正式案例/来源目录/写作者拿到既有完整材料。候选仅有可用独立精读或综述转述时也能被正式采用，不强制补 A/B。

新进程恢复会从已有 prior、落盘工具结果和当前读材料重建案例边界可用材料；只复用已经获得的资料。目标章节自己的来源内容和条件不能被另一章节同句柄记录覆盖。

### D. 案例缓存的实际依赖

先通过实际批次恢复复现了生效模型、输出上限和实时提示词变化后仍错误复用的问题，再把现有 `_cache_contract` 用到实际批次输入。没有新增缓存框架。

有两类担忧应撤回或限定：

- case thinking 实际固定 2048；仅改变通用 thinking 设置而实际调用不变，不应额外重算
- 已有材料变化若在模型实际投影裁剪之外，选择输入确实未变，不要求重新模型选择；但正式附加及 writer 仍必须拿到最新完整材料

目录移动等操作元数据不应无故使语义相同的批次重算。缺失合同或失败旧批次保持局部处理，不清空其他成功阶段。
