# F2/F3 formal adaptive consumer and recovery

All new evidence here is synthetic and offline. It is not the historical live chain, a provider replay, scientific acceptance, or a full BODY run. The locked production baseline is `6aee581`. No project key was read, no provider/network call was made, and no production prompt, BODY ordering, F4 identity/version policy, or case-selection behavior was changed.

## Results

- The 11 dedicated cases fail against unchanged `6aee581` and pass after repair. Three independent source-context cases also pass. The final focused selection is **111 passed**.
- An identical fulfilled request re-enters the real adaptive collector but makes zero additional model calls. The persisted need cache reports reuse; original successful attempt files remain unchanged.
- An ordinary failed resume does not pay again. Consecutive explicit failure retries reach the existing local attempt cache: the fixture has one successful initial partial read, two preserved failed expansion attempts, then one successful expansion. Useful partial content remains and the resolved gap is cleared.
- Same question with a new required output sends only the unmet output to the real local judge. Actual SQLite/WAL content change reaches a new real local-read request even while outer pool/plan inputs remain unchanged.
- A terminal stopped/partial journal can otherwise swallow explicit recovery after outer-cache bypass. The optional retry IDs reopen only the last attempted compatible nonanswered direction. Earlier useful material, query checkpoints, source context, consumed slots, and append-only history remain. The explicit attempt does not start a new research-round sequence; answered and other needs stay reusable.
- Pure local answer, partial/failure status, source identity, conditions, and limits reach actual `QwenProgressivePlanner` next-outline messages. The bounded projection omits raw local passages, attempt journals, source paths, and the complete candidate pool.
- A recovered exact need replaces its obsolete active chapter row. Historical stage/journal files remain; different acceptance/need IDs are not deleted. Compatible inherited prose retains its own sources, conditions, and genuine limits. Only the exact task-gap limit generated by the existing writer-material schema is removed once superseded; scientific limits are retained.

## Files

- `RESULTS.json`: selected actual before/after results, provider-boundary call counts, status/gap and active-row comparisons
- `ACTUAL_NEXT_OUTLINE_MESSAGES.json`: exact next-stage user-message strings for local completion, partial failure, and external completion; actual on-disk source-bound material alongside each message. Unchanged system prompts are omitted
- `DURABLE_RECOVERY_EXTRACTS.json`: complete saved local RESULT/FAILED records, hashes of real saved requests, selected exact need-cache/journal fields, and actual new-output/changed-index judge payloads
- `CHECKS.txt`: exact focused commands and results

Synthetic temporary roots in the JSON extracts are normalized to `<BASELINE_FIXTURE>` and `<REPAIRED_FIXTURE>`. Full temporary trees and duplicated prompts are omitted. Request SHA256 values describe the original unmodified request bytes, before path normalization in these extracts.

## Remaining boundaries

The formal CLI installs `make_retrieval_loop_runner`; that adaptive path is the repaired consumer. The legacy non-adaptive `_tool_cycle` branch without that runner is deliberately unchanged. A bounded probe confirms two identical explicit failed invocations still call its runner only once. This patch does not claim to repair every legacy tool path.

The collector still owns its existing material compatibility, local read cache, provider retry bounds, and shared deep-read budget. This work neither raises those bounds nor adds an automatic paid-retry loop. It does not establish scientific correctness, validate the historical source pool, or resolve F4/versioning or case-cache concerns. Context/tokenizer and model/network boundaries in fixtures are substituted; real provider behavior is untested.
