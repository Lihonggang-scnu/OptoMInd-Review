### Failure and concurrency recovery

- Concurrent different tasks use distinct deterministic task paths; concurrent exact tasks call the model boundary at most once.
- A stale incomplete observation cannot demote a newer committed retry. The regression uses real ordered store/reader calls, not a fake store.
- Historical falsely committed empty/partial artifacts are reclassified without deleting their evidence; normal completed reading locations remain immutable.
- Interrupted explicit retry with a saved bound RAW response resumes that newer response before considering an older empty artifact, with zero extra model calls.
- Foreign/unbound RAW is not used for another task. A conflicting task-owned directory fails closed with its original bytes intact.
- Real directory-creation failure after claim leaves the task pending and persists a failed attempt, with zero boundary calls.

## Unresolved items and risks

- Presence/coverage checks are not scientific verification; they cannot determine whether an answer is correct or sufficiently deep. `required_outputs` affects task identity; completion respects the existing question-based output contract, without demanding new output-ID fields from models.
- A missing question ID cannot prove full requested coverage: useful unkeyed/prose answers remain partial. Explicit unresolved flags are preserved, not linguistically guessed away.
- The in-memory material cache remains latest-task-per-paper. The real SQLite task store can reuse an older equivalent fulfilled task without another model call, verified across phases; no second material database was added.
- The empty-result retry flag intentionally rejects useful partials; a newly specified task/output can request additional reading. No automatic paid loop, full-source semantic cache validator or historical-run migration was introduced.
- No full review generation or quality acceptance is claimed.
- Work-order 03 query/retrieval orchestration repairs remain gated.
