# WO-07 — Run bounded short-chain acceptance and prepare cloud handoff

## Gate

WAITING_APPROVAL. Begin only after explicit approval following WO-06.

## Objective

Connect the repaired boundaries in short, inspectable offline chains. This work order is the final handoff check, not authorization for a complete planning, BODY, or publication run.

## Short chains

1. Empty query → existing query initialization → local-first retrieval or controlled external boundary → new material in pool → late-source route → case input.
2. Same need across stages → completion reuse → current identity rebinding → chapter-tool material and citation catalog → actual writer messages.
3. Same-paper new task → real directed-reading store/reader boundary → useful partial or new answer → owner update → resume without losing the update.
4. Owner task reorder/merge → arrangement source-brief handoff → writer body plus independent table → local export/record.

## Required controls

- Use real repair functions and only substitute model/network edges.
- Include a normal-path comparison with no recovery, no new material, and no oversized batch.
- Capture actual persisted outputs, call counts at the substitute boundary, cache/identity keys, and unresolved states.
- Submit a production diff summary, short-chain inputs/outputs, repaired/unrepaired finding list, and commands used to root for cloud review.
- Keep the case order and do not start a post-case whole-chapter review.

## Acceptance examples

The first chain records an initialized query rather than “no literature”; the second reuses complete research once while rebinding owner; the third stores a new task separately and keeps a partial answer visible; the fourth retains body and table and shows the original task IDs. A normal path remains unchanged.

## Record and limits

Use `RECORD_TEMPLATE.md` plus a short-chain appendix. Mark unavailable local fixtures `LOCAL_ONLY`. No paid calls, full review, full test suite, credentials, unbounded retry, or auto-publish. Root decides whether a later finite real run is separately authorized.
