# WO-06 — Consume complete writer outputs and judge completion by content

## Gate

WAITING_APPROVAL. Begin only after explicit approval following WO-04 and WO-05.

## Scope

- `optomind_research/runtime/upgrade3/review_unit_writer.py`: `parse_unit_body`, `run_unit_completion`, `_markdown_table_check`, `unit_messages`, and output/report helpers.
- `optomind_research/runtime/upgrade3/progressive_review_plan.py`: `run_feedback_loop` state consumption where it already consumes arrangement validation.
- Existing writer prompt contract only as needed to describe the output fields; do not encode the reviewed domain answer.

## Actions

1. Preserve a complete independent `table_markdown` alongside the body. If the same finished table is already in the body, avoid duplication. Do not mistake `table_tasks`, column requirements, or a proposed table description for a finished table.
2. Unwrap an outer Markdown code fence when it wraps the finished response while preserving actual code examples inside prose. Keep unknown citation handles visible in the report.
3. Repair numeric citations only when an explicit number-to-paper mapping exists. Never infer a paper from a matching P-number suffix.
4. Distinguish model omission from parser loss. Historical CH03/CH05 omissions remain writer-completion findings; parser support cannot claim to fix generation quality.
5. Judge completion by required objects, comparison dimensions, conditions, and explanations across body and table. Permit one table to satisfy multiple tasks when a bounded local human review shows all requirements. This is a local content check, not a semantic scoring service to implement. Do not use table count, paper count, or model self-report as proof.
6. Record the actual bounded model configuration used for any fixture and distinguish it from historical production settings. Do not change defaults as a substitute for this repair.
7. Apply unknown-citation and code-fence reporting to explicit completion/補写 paths as well as the ordinary writer path.
8. If the existing feedback loop sees incomplete arrangement validation, preserve valid output and report pending arrangement; do not launch paid writing merely because `units` is non-empty.

## Quality examples

Body plus independent table both survive parsing; a duplicate body/table is emitted once; only `table_tasks` fails completion; one table covering two tasks passes human review; missing required comparison fails; unknown handle is reported; unaffected unit text is unchanged.

## Dependencies and record

Use F17/F18 evidence and the arrangement identity/material handoff from WO-05. Record raw fixture shape, parsed body/table, completion judgment, citation report, fence handling, feedback-state decision, and the normal-path output. Any historical raw response not present in cloud is `LOCAL_ONLY`.

## Limits

No paid writing, full review, full test suite, credential access, automatic full-text remediation loop, or scientific-content hard-coding. WO-07 remains closed until explicit approval.
