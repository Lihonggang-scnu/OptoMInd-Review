# BODY 恢复与轻量首尾分离

更新时间：2026-10-01。本说明对应本地分支 `review-v2-manuscript-parts-local-acceptance`；不修改 `main` 或 `review-v2`，不表示已经合并或冻结。

## 目标

保留成功历史 BODY 的知识覆盖、具体案例和段落任务，只将文章级摘要、开场引言和收束结语分离到 `manuscript_parts_plan`。深度背景、理论讲解、机制、方法、比较和 Outlook 仍是 BODY 的工作，不能因标题含 Introduction 或 Conclusion 而删掉。

历史 176 篇引用稿是内容回归对照，不是新规划器的生产输入。新运行仍从原始研究 PLAN 和真实 A/B 材料池出发，不输入旧稿答案或题目专用的人工修改建议。

## 查明的退化

成功历史路径先完成全局协调及负责人修订，再把案例直接附加到具体单元。后来的 revision 路径改为先产生 `case_suggestions`，再让负责人完整重写章节；程序随后将建议归档。真实记录中，有些负责人保留了建议字段，却没有把它们形成最终案例，归档后这些材料不再进入写作计划。

另一处问题是部分章节初次 `chapter_details` 就没有 `paragraph_briefs`。不能把这件事误写成“负责人删掉了已有段落任务”；旧记录显示这些任务起初就缺失。

## 当前正文顺序

```text
provisional scope → 一级纲要 → 来源路由 → 章节提案 → 协调
→ 二级规划与材料工具 → 章节详细计划
→ 全局协调 → 负责人修订
→ 案例选择并直接补入 supporting_studies
→ 章内编排 → 单元写作 → BODY 装配
```

复用现有负责人和现有案例模块，不增加另一套 BODY planner。代码中的 `_post_case_review` 是历史函数名，现在主运行路径在案例扩展前调用它；不能根据函数名擅自把它移回案例之后。

案例模型的 `proposed_use` 是具体写作用途，兼容下游的 `contribution` 字段；论文方法、结果和条件由随附真实 A/B、精读和补充材料提供。若候选尚未加载到章节 packet，直接附加时从真实候选卡片补齐材料。保留旧路径按单元去重案例的行为。

已有实质单元缺少逐段任务时，现有负责人收到补齐 `paragraph_briefs` 的任务。整篇长综述恢复约 150–200 篇有明确用途的文献这一软目标；它不是每章配额，也不能用于加入无关论文。

## 首尾与保留的改进

职责卡仍沿用 v0→v1→v2，分别由 provisional、level1 和全局协调产生。最终首尾从职责卡、全局构思和实际 BODY 生成 Conclusion→Introduction→Abstract。

保留真实 A/B、精读、复数补充、本地片段、章节工具材料、负责人原任务交接、来源归并、引用编号、恢复运行和输出语言修正。恢复调度顺序不意味着回退这些已经接通的功能。

## 运行与验收

使用新目录运行，不覆盖旧稿或上一轮验收产物。旧的案例后 whole-plan/owner 结果不是当前顺序的有效结果；案例提示词合同已更新为 `case_groups.review_v2_04_body_append`，旧案例批次不能冒充新版生成。

先做离线内容通路核对，再从原始 PLAN 与完整真实材料跑一级纲要，确认深度 BODY 没有缩水后继续计划、编排和写作。验收看实际段落是否有背景、案例、比较、机制细节及有用的不同结果，不能用引用数或程序测试通过代替内容判断。

截至本文写入时，针对性测试已通过，新一级纲要真实运行已启动；完整 BODY 的恢复质量仍需以新稿亲读结果判定。
