# 恢复旧分单元写作入口，使用当前细纲与材料

## 2026-10-10 开发更新

本页下面的“30元本轮”及 `LOCAL_AGENT_HANDOFF.md` 对应先前179篇稿的历史实验，不是新实验授权。当前入口仍为 `scripts/upgrade3/legacy_unit_writer.py`；新运行的预算和账本须由调用者明确指定，成功结果与未知费用在恢复时保持。

在原作者之后可以显式启用 `--quality-control`：以实际正文和完整原任务/材料核查遗漏，最多补写一次并复核；有用正文和未解决问题分别保留。`--article-edit` 再用一次全文编辑处理相同用途的重复、术语、标题和承接。两步均使用 Plus，默认不开启，不改变原作者的提示词或向作者注入旧稿。实际任务完整性和科学正确性仍需结合落盘报告判断。

运行、保存响应恢复、显式失败重试及当前边界见 [质量与恢复接口](../writing_candidates/LEGACY_UNIT_QUALITY.md)。`--reparse-saved` 只免费重读已有返回；`--retry-failed --run` 才允许对已记录且没有可恢复正文的失败步骤建立新尝试。两者都不能清除旧费用或把未决结果当作完成。

## 策略调整

本轮主测试路线为：**当前细纲与材料 → 程序装配单元输入 → 旧分单元作者 → 确定性合稿**。

“细纲→指南→正文”保留为可选实验路线。它尚未稳定超过旧稿，本轮不以生成 GUIDE 为前置条件。上游规划不重跑；不将旧成功稿的句子、科学答案或引用清单装入模型输入。

复用的是旧作者处理细纲的机制：`paragraph_tasks`、各条 `source_brief_details`、`development`、来源用途、单元背景和表格任务直接进入作者。一个任务可展开为多个段落，多项任务也可综合成段，作者有写法自由。全文与章节框架负责定位当前单元。程序保留当前材料记录和明确的来源别名，不通过 LLM 再压缩一次细纲。

## 历史基线与本轮差异

历史基线：归档提交 `e0615b0f83ed001042b12c539a08a316f3ef6ab6` 的 `docs/acceptance/body40-20261005/`，实际受测源码 `7e293b63603157e741ec9b68f30565fcb4065f8a`。

- 该稿新生成七章、29 个单元、173 篇规范化去重文献。29 是该输入的单元数，不是生产规则。
- 29 个作者结果均标记 `qwen3.7-flash`。本轮用户明确指定 **qwen3.5-plus**。
- 历史主写作请求没有实际已写前文。本轮恢复这一分单元主写作方式；章节框架和同章其他单元安排提供组织背景。
- 生效提示词是 `load_writer_prompt(planning_revision=True)`，包含基础提示和运行时章节论证、原任务消费、写作保真、JSON 正文封装说明。仅阅读基础 Markdown 文件不能代表全部提示词。
- 本轮使用当前 `review_unit_writer` 的解析、引用兼容和材料能力，不将整个仓库退回旧提交。
- 原稿的 173 篇引用证明其覆盖能力，不等于全部引用正确或文章达到发表水平。旧稿仍有重复、个别来源错误和格式缺陷。

由于模型、材料版本与历史基线存在差异，本轮可判断恢复路线是否值得保留，不能把质量差异全部归因于某一个变量。用户要求先找相对最优，不为控制变量另开多路付费实验。

## 输入与提示词

输入使用当前完整 `FULL_BODY_INPUT.json`。来源应是细纲/编排与现有材料组装的 book，而非 GUIDE 的自然语言摘要。若从验收包还原大文件，按 `parts.json` 完整重组并核对哈希；若本地有相同原始文件，先核对其来源与内容。

当前题目已免费核验：29 单元、92 段落任务、3 表格任务及 14 行、194 个直接绑定的规范化来源身份。扩展到导航及工具依赖的身份集合更大，不能把只有身份/工具信息的记录算作完整文献供材。每章保留自己的来源快照，避免跨章同身份记录相互覆盖。

作者提示词沿用旧生效版本；当前需求中的“提示词紧凑”不转化为压缩正文。正文篇幅由解释、比较、反例及条件决定。最终希望实际引用至少 150 篇不同文献；统计是结果评价，不通过程序插入引用、照搬旧参考文献或预借未生成引言达标。

默认预览保存实际发送的完整消息，便于本地检查生效提示词和真实供材，而不仅是模板文件。

## 预算与执行边界

本轮获批 **新的独立 30 元预算**，只用于本轮旧路线的 Plus 写作测试。正式运行须显式指定 `--ledger`，新建专用账本并在恢复时沿用，原指南、正文和审查账本均不改动。硬上限含全部重试、恢复或补写调用；不因换输出目录而重新获得 30 元。

本地先进行全单元免费预览、真实 tokenizer 容量检查和输入核对，再付费生成。记录 tokenizer、模型配置、实际源码提交和输入哈希。UTF-8 保守上界不是实测 token 数，也不是实际费用。所有单元的最大输出额度之和可能超过 30 元，这个最坏上界不要求提前占用；实际运行逐次占额并执行总账本硬上限，余额不足时停下。每次调用前保留预算占额；未决费用先核对，避免重复收费。

无自动切换 Max、无付费审查循环。有效返回、失败现场与原始响应保留。重试只针对明确失败且费用已核清的单元，成功单元依同输入缓存恢复。

## 本地验收重点

1. 是否真实使用当前细纲、完整材料和旧生效作者提示词，未经过 GUIDE 压缩，未混入旧稿。
2. 分别统计输入单元/任务/来源与输出正文；覆盖率不以 LLM 自报完成替代亲读。
3. 完整阅读七章，优先看解释深度、重要比较、阴性结果、条件、表格，以及重复与承接。引用数量和科学引用正确性分开评价。
4. 以实际规范化身份统计去重引用，区分直接供材、仅导航、别名重复和未知来源。未引用来源按实际用途抽核，不一概视为冗余，也不强行塞满引用。
5. 与十月五日 173 篇稿及最近 117 篇稿对照；旧稿只用于测试后的评价。报告改善与退步的具体文本位置。
6. 保存请求、原始返回、配置、费用、恢复记录和正文。公开归档排除密钥、账本数据库、未经授权论文全文及个人本地信息。

允许局部缺陷。完成一轮完整测试后停止新增付费调用，由用户和云端复读决定是否保留。
