# 产品工作宗旨

用户明确要求：**严格拒绝过度防御。产品实际质量、解决问题的能力和结果的帮助性优先。**

这条要求适用于云端开发、本地开发、实验安排、审稿与交接。

- 工作的终点是有用的产品与实际改善，不是收集可以免责的结论。
- 发现明确瓶颈，优先修好。验证用于发现错误、确认改动生效和保住已有好成果，不把实现拖成无休止的归因实验。
- 对复杂科研理解与写作，先给模型合理的材料、推理和回答空间，再优化费用。不要因为很低额度能跑通，就默认它足以做好任务。
- 用户配置必须落实到实际请求。有效配置、使用量与输出要能核对，避免上层要求充分思考、下层却关闭或压低。
- 不用测试数量、引用数量、字数或 JSON 成功状态替代内容价值。读实际产物，改善任务展开、比较、条件、案例和综合。
- 只提出会影响行动的风险，并给出解决办法。避免反复堆叠“不宣称”“不能归因”等与交付无关的防御性表述。
- 保住好内容和可恢复产物，保留必要的费用、身份、材料与运行边界；不要把这些做成阻止有用工作的复杂平台。
- 面向不同学科做通用链路，不把本次测试文章的科学答案写进提示词。

## 当前优先工作

先解除不合理的小推理配额和参数传递问题，补齐已有条件与论证关系的交接，然后使用充分配置继续细纲与写作改进。无需额外组织一轮只为证明“大预算是否比小预算好”的科学实验。
