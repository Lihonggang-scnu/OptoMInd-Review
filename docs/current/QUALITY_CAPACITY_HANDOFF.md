### 关键参数规则

1. `max_output_tokens` / CLI `--output-tokens` 仍表示**回答空间**，保持现有调用接口易用。
2. 支持的Qwen模型实际HTTP请求改发 `max_completion_tokens = 回答空间 + 思考预算`；不会同时发送旧 `max_tokens`。
3. 局部Max修订32,768思考＋32,768回答，合计65,536；整章配置32,768思考＋65,536回答，合计98,304。不要把回答额度直接当合计再扣掉思考。
4. 运行结果、账本、相关阶段产物保存 `effective_request` 和 `cap_pressure`。前者记录实际发送值；后者是预算用量提示，不自动阻断可用产物。
5. 规划器的 `--thinking-budget` 与 `--output-tokens` 适用于所有规划阶段；不再在细化、案例、协调和负责人中偷偷覆盖。定向精读使用独立明确的reader参数。
6. 显式配置可以覆盖默认值；不要复制旧实验中的 `WRITER_THINKING=0`、`ARR_THINKING=1024` 等常量。新产物要有自己的实际请求记录。
7. 规划、编排及自动精读缓存检查实际参数；显式历史精读仍可作为素材复用。新实验用新的输出目录，别把旧响应命中算作新调用。

容量上限不是目标字数，也不是要求模型用满思考。优先保留相关完整材料、邻近单元职责、条件和已有有效细纲。

### 2 复用同一批真实材料 先形成一个更好的结果

优先复用上一轮两个关联单元、相关完整材料及已经验收的正文。补上该章其他单元的职责摘要，避免把“这次没提供的单元”误认成“整章漏掉的知识”。

第一步用充分配置的强模型一次修订，采用现有负责人输出合同；保留任务身份、具体案例、条件、阴性结果和来源用途。随后进入当前生产编排和写作，亲读产物。

如果主要问题已经解决，就保留结果，节省后续调用。如果仍有明确的职责冲突、比较缺失或薄弱综合，再让独立审稿提出这些具体问题，由现有负责人针对性修订；必要时只重写受影响单元。两阶段应解决第一步留下的真实问题，不为凑齐实验组而重复整套流程。

### 3 根据问题实际所在位置处理

- 细纲没有分配好知识任务：修改细纲/负责人结果。
- 细纲任务正确、实际writer输入也完整，正文却漏做：用现有定点补写入口补足任务，保住好段落，不再来回改纲。
- 材料/条件没送到：修交接或配置，不让模型用常识猜。
- 过度推论、研究归属错误：带对应材料做局部修订，不重写整章。

检查实际消息中有没有要求过度简写的指令。按功能判断，不全局删除“brief”等词：段落任务的简要描述和要求成品正文省略分析是两回事。

### 4 内容判断与停点

本地GPT6.1 sol亲自读细纲、输入和正文，重点回答：职责分工更清楚了吗，比较关系真正写出来了吗，机制与研究条件保住了吗，阴性结果被公平解释了吗，原有好内容有没有被改坏。自动换序评价只辅助定位，发现内容归属混淆就回原文核对。

综述转述的原始研究，只要内容可用、引用身份明确，照常使用，不按来源层级降权。一张充分的表可以完成多个任务。不要追逐篇数、字数或表格配额。

先交付这个任务簇的可用改进，再决定扩到全章或其他领域。已有真实进步就保留，不等到每一个指标都有完美结论。
