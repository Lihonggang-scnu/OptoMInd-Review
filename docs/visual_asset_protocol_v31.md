# Visual Asset Protocol v3.1

This protocol stores visual evidence extracted from scientific papers. It is
designed for downstream literature reviews and research plans that need to cite
figures, tables, spectra, micrographs, device diagrams, and the paper text that
explains them.

The protocol separates three layers:

1. `visual_asset`: factual extraction record. It should be produced mostly by
   deterministic tools.
2. `visual_card`: interpretation record generated by a vision-language model
   from one visual asset plus caption and linked text.
3. `paper_card`: paper-level synthesis that merges full text, chunks, visual
   assets, and visual cards.

## Design choices

- `source_provenance` follows the direction of Docling/GROBID/JATS: every visual
  item should know its source file, parser, page, coordinates, and source node
  when available.
- `text_linkage` follows the PaperQA2-style media-to-chunk relationship: a
  visual item should be linked to body callouts, not only to its caption.
- `domain_hints` is OptoMind-specific. For optical films, the downstream review
  needs to know whether a visual item is a spectrum, material structure, device
  schematic, thermal image, benchmark curve, or process flow.
- `visual_asset` should avoid model interpretation. Qwen-VL should write
  `visual_card`, not overwrite the factual extraction record.

## Parser priority

1. `publisher_html`: use a DOM extractor. It usually preserves figure nodes,
   captions, tables, image URLs, and section hierarchy.
2. `pdf`: use Docling with short temporary paths, `--no-ocr`,
   `--pdf-backend pypdfium2`, and `--image-export-mode referenced`.
3. `pdf` fallback: use PyMuPDF page rendering and caption-region cropping.
4. `html_markdown`: use text and callout extraction only. It usually has no
   recoverable images. Try source recall to fetch publisher HTML or PDF when
   possible.
