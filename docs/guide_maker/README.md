# 细纲转写作指南

这是独立于正文作者的中间层。先把批准细纲加工成可继续完善的写作指南，再按具体写作需求读取材料，最后输出可以直接交给 `guided_body_writer.py` 的指南文件。现有正文作者和规划层不作修改。

## 工作流程

1. 模型先看到完整细纲和轻量文献导航，不默认接收全文材料池、旧正文或人工 A/B 指南。
2. 模型给出初步全文指南，以及会影响写法的阅读需求：需要看清怎样的比较、解释关系或重复内容的新用途，并指出候选来源。
3. 程序取回请求的完整相关科学对象。容量不足时按完整材料包分批，不把记录截成固定字数片段。
4. 模型保留已有安排并更新指南。记录读取的问题、实际交付的材料，以及指南哪些部分发生变化；仍有必要需求时继续，达到轮次或容量限制时保留草稿并停止。

不预设阅读篇数，不按固定 top-K 决定科学材料，不要求对每个细纲任务制作对应表。程序只负责输入、读取、保存、容量和预算。没有自动科学审稿器，也不会生成指南后自动调用正文作者。

## 指南的写法决定

指南应明确重复材料在哪里主讲、后章增加什么、哪些内容只回指；利用细纲已给出的具体关系安排解释的深浅和顺序；按有意义的维度与适用条件组织比较；说明章节如何推进读者的认识。不能以章节摘要、标签列表、统一解释模板或反复强调相同缺口替代这些决定。

2026-10-09 定点修订进一步强调：主讲分配只调整详略，不取消其他章节的独立用途或规定图表；合并时保留解释、对照、反例和相应来源作用；局部写法不扩大成逐段义务；压缩不改变条件、可能性或并存关系。仍使用原指南字段，在同一次生成内协调全文与各章安排，不新增映射表或评审调用。允许非关键缺陷，以相对更好的可用版本为目标。修订理由、明确 Max 候选配置和本地测试步骤见 [本轮交接](PROMPT_RETENTION_RETEST_20261009.md)。

完成意味着组织决定已经可用，不只是 JSON 完整。补读仅用于尚未解决且会改变写法的选择，允许资料已足够时零补读；不添加任务映射、审稿阶段或新指南字段。离线测试只能检查协议和提示约束，不能证明真实生成的指南质量提高。

本次保留完整细纲投影及 owner 上下文。暂不折叠重复框架：相似字段仍可能包含归属、独特条件或任务要求。现有严格相等的 task_catalog 去重保持不变，规划文件始终只读。

## 输入

使用现有真实 manifest 或封存 book。规划内容只读，完整的章节、单元、段落职责和规定表格进入细纲投影；执行日志和材料存储包装不进入首次模型视图。

目录使用已有来源身份、资料类型、内容线索和章节单元关联，不能凭空补齐缺失类型。导航字段是有意选择的目录，不是全部文献内容；被省略的科学详情保留在材料档案中供选读。

已有工具补充也有独立导航和读取路径，避免只允许读普通文献记录而遗漏此前工具找到的内容。工具导航句柄仅用于本次读取，不成为新的论文引用编号。

`--feedback` 是可选的 UTF-8 阅读反馈文件。没有旧稿或反馈时正常冷启动。测试自动选读时优先不提供人工指南、手选论文名单或旧稿评价，以区分中间层自身能力与已有反馈的帮助。

## 阅读与上下文

每个需求包含简短问题和精确来源句柄，也可指定已知原子或工具导航句柄。材料保留结果、方法、条件、限制和互补版本；相同科学值不在多个包装中反复发送。

每轮只发送本轮材料、当前完整指南、细纲导航和紧凑阅读历史，不无限累积全部已读原文。详细材料仍存档，需要回看时给出新的 `reread_reason`。重复无目的读取会停止，不产生无限付费循环。

真实请求使用现有 tokenizer 计量及输出预留。若一个完整材料包也放不下，记录阻断，不静默截断。保守估算不等于实际模型 token 数；本地正式运行应提供匹配的 tokenizer。

## 输出

- `GUIDE.json`：仅完成后发布，格式与现有指南驱动作者一致。
- `GUIDE.md`：可阅读的最终指南。
- `DRAFT_GUIDE.json` / `.md`：尚未完成的最新有效草稿。
- `GUIDE_RESULT.json`：本次状态、费用、未解决需求和版本。
- `READ_TRACE.json`：需求、材料、指南前后版本及可观察修改。
- `runs/`、`stages/`、`reads/`：实际请求、响应、材料包和恢复资料。

“修改发生在补读之后”是可观察轨迹，不自动证明修改更好。指南是否改善全文仍需交给同一个正文作者比较。

## 默认运行

```powershell
python -X utf8 scripts/upgrade3/guide_maker.py --manifest "<真实 PREPARED_MANIFEST.json>" --config config/guide_maker/plus_first.json --tokenizer "<现有 tokenizer.json>" --output "<新的指南生成输出目录>"
```

默认免费预览；`--responses` 为离线录制；`--book` 只用于离线封存资料。`--run` 才是显式付费运行。

完成后另行调用作者：

```powershell
python -X utf8 scripts/upgrade3/guided_body_writer.py --manifest "<同一真实 PREPARED_MANIFEST.json>" --guide "<指南生成输出目录>\GUIDE.json" --config config/guided_body_writer/plus_first.json --tokenizer "<现有 tokenizer.json>" --output "<新的正文输出目录>"
```

两条命令不自动串成付费流水线。正文预览通过后是否付费写作，按本地测试安排执行。

## 预算与恢复

默认 `--budget-mode legacy` 沿用原 round-two 60 元终身累计账本。显式 `--budget-mode dedicated --budget-limit 30` 可使用指南专用账本（上限不得超过 30 元），原账本或已有专用账本的花费及未决占额均不得重置。专用账本身份标记、路径、上限与恢复运行绑定，拒绝接管未标记的外来账本。正文作者的预算入口不变。默认 Plus，最多 8 个逻辑模型阶段，不自动升级 Max，不隐式重试未知花费。

成功阶段可缓存复用。后续失败不抹掉已有指南草稿，只有完整指南才作为本次完成产物。因轮次上限停止，可在其他配置、输入和提示不变的条件下提高 `max_model_calls` 继续；不得用此方式绕过终身预算。

当前中间层复测使用已有独立 30 元账本，见 [本地测试说明](LOCAL_AGENT_HANDOFF.md)。归档余额不是实时余额；运行前读取真实账本。提示或实现改变后必须用新输出目录，但继续使用同一账本。

用户另行批准 Max 测试时，可显式选择 `config/guide_maker/explicit_max.json` 并传 `--allow-max`；默认配置仍为 Plus，不自动升级。新增配置仅复用仓库已有 `qwen3.8-max` 适配，不代表云端验证了服务商当前价格或可用性。允许模型不等于授予无限预算；不要因选择 Max 重置或扩大旧账本。最新交接中的运行边界优先于旧轮次说明。

## 通用性和验证边界

运行时不含当前文章的菌名、癌种、论文名单或七章模板。文章结构和领域均来自输入；测试使用不同领域的小样例，并以真实七章资料检查材料体量和接线。

离线录制只能验证工作流程、材料读取、缓存、容量和直接接入作者，不能证明 Qwen 已具备人工指南的质量。具体测试结果见 `verification/VALIDATION.md`。
