# 本地供材第二轮返修指令

## 起点和范围

以 `2df2a2719b17b05a9ccdfc1574b0649c7bacf586` 为基线，建立独立修复分支。先读本目录 README、ASTRA_ACCEPTANCE 和四次真实调用的请求元数据及模型结果，再阅读既有 `docs/acceptance/body03-20261003/records/local_lookup_repair.md`。先在 records/00.md 用自己的话确认两个真实损失点，不沿用旧报告的“身份命中等于供材通过”判断。

本轮只修本地检索与阅读供材。主要落点是 `optomind_research/runtime/upgrade3/planning_material_triage.py` 的 `prepare_local_reading`、`read_local_capture`，以及 `planning_material_search.py` 的 `search`、选段与卡片上下文帮助函数。如必须动共享 search，先列出其他调用者；优先以可选参数或本地阅读专用帮助函数限制影响。

不改 BODY 规划提示词、执行顺序、案例、编排、writer、科学判读提示词；不新增 planner、重读平台或第二套材料库。不按 P0004、PDAC、某个科学答案或术语硬编码。不追求模型措辞零错误。本轮云端零真实模型、零外部检索下载，不接密钥，不跑全稿，04–07不启动。

## 任务一：扩大方向不能丢掉原问题

现状：`read_local_capture` 将原问题和判读器 read_focus 拼成一个长检索请求，重新排序后，原问题中很靠前的论文可能退出窗口。真实测试中目标由默认排名9变成64；新增材料预算尚未耗尽。

实施要求：

1. 保留原 question 独立检索所得的有界候选作为扩大阶段的主锚点。read_focus 单独提供补充候选或补充选段，不能替代原问题。
2. 合并两路候选时按稳定身份去重，原先有效片段始终保留。对每个被选论文按原问题及新增方向选择有用片段，不能仅把两路 ID 合并但仍只给旧的前三篇分片段。
3. 保持一次扩大、现有候选上限及新增字符上限。原问题已覆盖的来源优先，不要求两路平均分配；实现选择规则要明确、能在实际 payload 中检查。超预算时取舍必须同时考虑来源覆盖与内容，不能只靠提高 top_papers。
4. 不重复触发模型、不依赖追加查询改写调用。相同有效输入仍复用，输入材料真的改变时不能沿用旧判读。

第一项验收：先建反例——原问题的对点候选在12篇窗口内，加入宽泛 read_focus 后排到窗口外。修复后，相关材料实际进入判读请求，再进入可交付材料；不是只出现在候选名单。保留原始失败版本供对照。

## 任务二：指定论文必须读到其问题相关内容

现状：提名论文仅取 production search 的1段；真实 P0004 的原始受限FTS首位是免疫治疗段，最终却选成代谢物段。paper_context 又仅覆盖提名前初始论文，提名论文已有 A/B 的关键认识未进入请求。

实施要求：

1. 逐步检查原始受限FTS候选→重打分→选段→邻段拼接→实际payload的路径，记录为何首位对点段被丢失。不要凭 BM25 第一名总是正确，也不要凭当前重打分第一名总是正确。
2. 指定稳定身份论文保留一个小规模、多信息渠道的材料包：已有 A/B 中的研究认识与相关贡献、该论文的 bounded paper_context、少量问题相关正文片段。可先用2–3个互补片段；不全文灌入，也不只是 scope/题名/身份。
3. 在同论文内保留问题相关的词法命中通道，避免全部由通用词频重打分覆盖；去掉重复与参考文献列表等非内容。是否需要改打分，由反例与其他学科测试决定，不能一刀切废掉现有排名。
4. 将提名论文纳入上下文配额的实际选择。若无卡片，正文片段仍可用；若只有有用的综述转述及原始研究引用身份，不强制原始研究有 A/B 或全文。
5. 所有新增内容在当前总阅读预算内，保留已有 `explicit_reading_status`、partial、失败尝试、原有效材料与重试目录。不要强制判为 fulfilled。

第二项验收：模拟一篇多章节论文，其中通用高频段与问题相关段竞争；已有 A/B 另有补充认识。必须断言判读器实际收到问题相关段、关键认识以及该提名论文上下文，随后交付材料能保留它们。不能仅断言 paper_id 或字符数。
