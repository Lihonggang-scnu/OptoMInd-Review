# 本地实验：一次 Plus 审查 → 一次 Max 判断修订

## 目的与停止点

只检验一次审查是否让**已有完整指南**更值得交给正文作者。保留原指南作为对照，不重新付费生成基线，不生成正文。本轮新预算总上限 **30 元人民币**，不是每个角色各 30 元，也不是必须花完。正常路径最多一次 `qwen3.5-plus` 审查和一次 `qwen3.8-max` 修订。没有自动返工循环、付费失败重试或额外模型补读。

该实验是独立入口，原 `guide_maker.py` 默认流程不变。无效果时停止使用此入口，仅保留 [章内供材与提示词小补丁](SOURCE_HANDOFF_20261009.md)。不需要回退整个分支。

## 输入 → 输出

- 输入：同一份真实材料 manifest、已完成的基线 GUIDE、模型配置、本地 tokenizer。
- Plus：完整基线指南、完整细纲、轻量文献/工具目录，以及指南明确关联来源的完整材料包。程序按两角色容量保留完整包，不填满全目录、不截断包。`material_scope` 明示实际提供和未提供范围。
- Plus 输出：至多六项重要、具体、可局部处理的意见，可为零项；给出指南定位、输入中的依据及局部建议。没有每章配额、不要求找足六项。
- Max：上述相同资料，加 Plus 意见；逐条接受、部分接受或拒绝，并给出简短理由。仅修改合理部分，保留已有优点、语言、组织自主性与限定条件，不把审查当作新细纲。没有有效意见时允许原样保留。
- 输出：`BASELINE_GUIDE.json/.md`、`REVIEW.json`、`REVISED_GUIDE.json/.md`、`DECISIONS.json`、`REVIEW_RESULT.json`，以及实际请求、原始返回、失败记录、配置、费用和供材范围。

`complete=true` 只表示这次两阶段协议完成。修订版仍是候选，默认选择保持基线；本地比较和云端亲审后再决定交给作者哪版。目录存在不等于已读，引用身份成功不等于科学引用正确。

## 本地开工顺序

1. 拉取 `lihonggang-dev`，记录实际受测提交；不要把归档提交当受测代码。
2. 复用上轮 Max 的原材料 manifest、完整恢复后的指南和 tokenizer。可直接使用仓库中的 `docs/acceptance/guide-maker-max-retest-20261009/guide/GUIDE_RECOVERED_FOR_REVIEW.json` 作为基线。不要先人工修改里面的已知内容缺陷，否则不能区分审查收益。
3. 保存基线 SHA256。实验输出使用新的独立目录，不能写回原生成目录。使用本轮新建且固定的 30 元专用账本；续跑必须复用同一账本、上限和输出目录，不删除数据库/标记重置余额。
4. 先免费预览，检查两角色配置、供材范围、完整细纲、Max 审查反馈预留空间和输入容量。不要把 UTF-8 字节保守上界当真实 token；正式运行使用本地已有 tokenizer。
5. 运行一次实验。不要因审查意见不理想再抽样。遇到格式/传输失败保留失败记录和基线，不自行增加付费重试或换模型。
6. 对基线和候选分别做七章作者免费输入检查。核对材料实际内容是否进入请求、各章组织及来源身份能否交付，不生成论文。
7. 独立比较后上传冷启动验收包，由云端亲审选相对更好者，结束指南阶段。

### 免费预览命令

以下尖括号内容由本地 Agent 替换为已经存在、验证过的实际路径，不猜测 manifest 或密钥路径：

```powershell
python scripts/upgrade3/guide_review.py --manifest "<上轮真实材料manifest.json>" --guide "<完整基线GUIDE.json>" --output "<本轮独立输出目录>" --tokenizer "<现有tokenizer.json>"
```

配置默认是 `config/guide_review/plus_max_once.json`。Plus 预留思考 8,192、答案 12,288 tokens；Max 预留思考 32,768、答案 32,768 tokens。沿用现有底层传参和预算计量，不能把答案预算误当思考加答案总量。

### 显式真实运行

```powershell
python scripts/upgrade3/guide_review.py --manifest "<上轮真实材料manifest.json>" --guide "<完整基线GUIDE.json>" --output "<与预览相同目录>" --tokenizer "<与预览相同tokenizer.json>" --budget-ledger "<本轮固定30元专用账本.sqlite>" --budget-limit 30 --run --allow-max
```

复用现有本地安全凭据配置。若确需 `--key-file`，由本地 Agent 使用已有私有路径，禁止将密钥或含密钥的配置上传。专用账本复用既有 guide ledger 机制，旁边的 `.guide_maker.json` 标记是正常现象；不是旧账本可以重置的许可。

`--book` 只供封存材料的免费预览/录制回放；真实运行必须用 `--manifest`。没有 `--retry-failed`。同一输入成功续跑复用结果；输入、配置、提示词、材料选择或执行方式变化，不应冒充原实验续跑。

## 怎么判断是否值得保留

先读原指南与候选，再读 Plus 意见和 Max 决定，避免只按审查条数打分。重点举具体前后例子：

- 原本无人接收的解释、比较或反例是否真的有了位置？
- 主讲与后章新增内容是否更清楚，重复是否减少？
- 原有好内容、来源作用、条件和规定图表有没有被删薄？
- Max 是否能拒绝不合理意见，是否引入新模板、过强措辞或科学纠错错误？
- 提升是否足以抵偿新增一次 Plus 和一次 Max 的成本？

不要以篇幅更长、措辞更保守、接受意见更多或 JSON 合法判为胜出。允许小缺陷，不要求所有问题清零；没有明显净收益就保留基线和小补丁。
