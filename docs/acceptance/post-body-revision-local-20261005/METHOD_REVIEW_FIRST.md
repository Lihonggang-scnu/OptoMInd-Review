# 请先评价实验方式，再评价候选结果

这是给云端顾问的本地实验交接，不是上线推荐书。请独立判断；本地评价也可能错误。

## 用户目标与本轮实际范围

用户关心的是：什么机制能明显提升细纲与最终文章，值得加入长期通用链路，而不是修好某一篇测试文章。本轮实际运行的是独立 **post-BODY 局部修订模块**，没有修改、重新生成或比较新细纲。因此这批结果不能回答“细纲是否明显改善”。如果实验范围与用户目标不匹配，请先指出，不必在 A/B/C 中强行选赢家。

## 建议先审查的事实

1. 固定同一份真实 BODY、最终细纲及素材，选择三个局部问题，没有预写替换答案。只有 R1 是明确因果措辞问题；R2 是同试验复用是否具有解释增量，R3 是内容保留对照，后两者可以合理不改。三个问题都来自同一个学科，同一份稿件。
2. A 全文综合阶段读全文、细纲和材料导航，但导航不是研究结果；后续核验才读选中材料。B/C 跳过自主发现，局部作者和核验直接读选中 A/B 等内容。信息可见性和流程同时变化，不能把差异纯归因于多步设计。
3. A 首轮固定问题协议失败，追加一段通用固定模式指令后重试一次。失败请求、输出、费用和实际源码差异均保存；不要将前后视为完全相同的提示词。
4. 全部实际调用都是 qwen3.7-flash。C 配置虽允许 qwen3.5-plus 升级，本轮没有触发，不能据此判断强模型收益。
5. B 有一次超时；恢复时四个成功结果严格回放，仅失败核验新调用。其完整已知费用包含原尝试，未知费用继续占额；恢复报告的增量费用不能当完整成本。固定模式还省略了发现成本。
6. 评价者隐藏了方案标签，但此前读过部分原稿；不是全新上下文严格盲评。左右交换包准备过，未另行完成交换复评。原始判断与一字段一致性修订均保存，不能只读修订版；C 的 loss 标记指原稿侧的方法说明，不是候选新增知识损失。
7. 92 项离线检查验证运行与定位合同，不能证明修改有实质价值。applied/verified 数量也不能代表有效改进：B 的一个补丁仅改变换行。

## 推荐阅读顺序

- 本说明与 README、选择/省略清单、源码版本和差异。
- 三个固定问题、实际配置、命令及实际 provider 请求，检查模型到底看到了什么。
- 原 BODY 与各候选、原始响应和供应素材；先独立评价，再读本地亲审。
- 独立评价原件、限制、费用账及 ROOT_EXPERIMENT_REVIEW.md。本地报告是待你检验的判断，不是金标准。

原始模型输出与人工说明分开；公开投影如有删字段，应查其省略记录。项目生成素材不等于重新核验原始论文全文，卡片未提到某方法也不能证明论文没有该方法。

## 请你帮助判断的问题

1. 这个固定三问题试验适合回答什么，不适合回答什么？哪些比较受到输入差异、保留对照、共享模型误读或评价方式影响？
2. 逐项看实际改动：是否准确、解释是否更好、重要条件及负面结果是否保留？尤其 R1 是否真的分清总体与用药亚组，R3 改法和理由是否分别成立？合理不改不能当失败。
3. 是否有任何方案已有足够证据进入系统？若只证明局部小修，请直接这样说。B 作为下一轮实验路线的建议不等于生产推荐，也没有得到细纲改进证明。
4. 下一步最划算的是调整实验问题/材料、改善核验，还是先对细纲进行全局诊断并定向重构论述单元？请依据代码与证据决定，不预设需要更复杂架构或更贵模型。

建议你先简要汇报“实验方式是否成立、结果支持到哪一步、下一步最值得验证什么”，再提供一份有边界的方案。此次交接仅供阅读和判断，没有授权云端付费调用、完整 BODY 重跑或自动合并。
