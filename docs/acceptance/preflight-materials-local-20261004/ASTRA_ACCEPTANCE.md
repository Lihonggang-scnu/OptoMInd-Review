## 新发现及建议交给云端判断的收尾

### 1. 实际引用被漏统计：建议优先处理

正文出现 `[参考单元论证][P0602]` 等组合。正式 `citations_in` 将其按 Markdown 参考链接的相邻括号规则跳过。

- 本次正文实际含 7 个不同的规范 `[Pxxxx]` 引用。
- 正式 `UNIT_RESULT.json.used_source_handles` 只报告 P0576，其他 6 篇被误列为未用。
- 最小复现：`x[P0602]` 能识别；`x[参考单元论证][P0602]` 返回空；正常 `[P0564][P0576]` 能识别。
- 内容和引用没有从正文消失，但统计与后续缺引用判断会失真。

证据在 `ROOT_CITATION_CONSUMPTION.json`。建议结合真正的 Markdown 参考链接定义与已知单元来源判断，而不是泛化删除括号文字或把所有括号都当引用；保留链接、图片和代码反例。说明性占位文字本身也应作为输出问题识别。该处未在本地改生产代码。

### 2. Windows 单元身份进入文件名：建议在完整运行前收尾

真实单元身份是 `CH02:U3`。正式 writer CLI 拼出 `CH02_CH02:U3` 目录，在本机准备输入时失败；运行库原始响应名仍包含冒号，在 NTFS 上落为备用数据流。

本轮用驱动的安全目录跑通生产运行库，并将已生成 raw 从原位置复制为普通 `RAW_RESPONSE.json` 便于检查。没有重发模型请求。这不等于正式 CLI 路径已修好。

建议统一处理运行目录、普通 raw 文件和补写文件的路径组件，保持 JSON 中科学任务 ID 不变。成本低且能防止完整运行在写作开始时卡住，不需要改写作逻辑。

### 3. 同内容目录迁移仍可能使案例选择缓存失效：较小费用问题

真实历史 loader 接受同内容迁移，但生成的 `reused_from` 路径不同。该路径进入 `case_groups` 缓存合同，导致合同不同；诊断性地只去掉这个路径后合同相同。

影响是可能多调用一次案例选择，不是精读一定全部重跑。建议在既有有效输入投影里处理这个操作性路径；科学内容、条件和任务变化仍应失效。尚未做生产修复。

### 4. 仅作为时序风险记录，不认定真实丢失

受控地移除一个已有 A/B 行中的 deep，同时仅在独立 map 放入 deep，案例 resolver 会保留旧实质行而不补 deep。但当前真实 packet 的 P0582 已有 A/B 和 deep；正常 chapter/owner 供材有预先合并。不能拿这一受控时序探针当成当前真实丢材料的证明，也不建议据此直接覆盖所有章节材料。
