# 用户需求与本地执行的区分

用户批准独立测试“细纲→写作指南”中间层，与另一个助手的人工A/B指南→正文任务并行。固定9a5e1d90，独立worktree、输出和新30元账本。复用真实manifest/tokenizer/材料，不重跑检索、精读、规划；默认plus_first配置走正式guide_maker CLI，不用简化脚本。

用户期望冷启动实际收到完整细纲、轻量来源与可选工具目录；不输入人工指南、旧正文/旧稿评价或人工挑选材料。模型自行形成指南、提出组织/解释/比较/详略相关阅读需求，程序返回完整有条件的科学内容单元，再自主改进指南。完成后只做免费作者接口预览。

用户要求亲读全文组织、重复内容主讲与复用增量、解释深度/比较/衔接、局部张力、任务书和模板口吻，以及补读是否有用、实际读了什么、指南如何变化。JSON合法与流程完成不等于质量合格；修复需跨领域通用，不把测试科学答案放进生产提示。

用户允许必要工程小修，要求保留首次与失败记录；大流程或大提示改动先给实例与方案。本地先保存完整包，后来明确授权上传供云端阅读分析。实际情况是一次Plus调用，没有阅读需求；不能把用户设想的补读流程当成已经发生，也不能把本地报告中的建议当成用户既定方案。
