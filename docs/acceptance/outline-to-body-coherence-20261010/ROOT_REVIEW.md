# 采用决定：正式接入现版 baseline

现版是用户认可的高质量综述初稿基线。本轮新提示有局部改善，但没有清楚的净收益，因此正式入口采用 baseline，默认启用已经有效的任务落实核查、有界补写和一次全文局部编辑。chapter_coherence 保留为显式实验选项，不自动启用，不追加下一轮抽样。

## 本轮实际比较

固定同一 FULL_BODY_INPUT、原任务与材料，选择 Ch1/U4、Ch2/U03、Ch5/U01、Ch5/U04、Ch6/U3 五个单元：四处共享临床案例用于检查分工和重复，一个富机制单元用于检查知识保留。两臂都是全新 Plus 作者，不把旧稿或人工科学问题喂给模型。

- 作者：qwen3.5-plus，8,192 思考、32,768 回答，总输出额度 40,960，流式直连。
- 现有任务核查及 post：qwen3.5-plus，16,384 思考、24,576 回答，总输出额度 40,960。
- 两臂均使用现有核查与一次有界补写；单元子集不做全篇编辑。
- baseline 从 73f938e 的固定源码导出执行，五个作者消息与该基线既有同输入消息一致。
- 候选从 1e01821 执行正常 run_review_harness BODY 入口。原29个单元任务、条件、来源用途与材料字段在免费预览中逐项保留；只增加从实际全篇细纲投影出的职责上下文和通用增量提示。

初次候选启动在发送请求前遭遇研究路径的 economy ceiling，模型调用为0。已修复正式 BODY 路径的这一接缝，并用真正脚本 main、原有模型工厂、模拟 SSE 和双账本验证后显式恢复。旧失败尝试保留。这次入口修复与写作质量方案分别评价。

## 亲读看到的收益与代价

1. **Ch5/U01 有局部收益。** 新稿不再在疗效介绍中完整插入心肌炎等安全性数据，更多展开有害菌清除、代谢功能与随机试验局限。核查自动提出一处在已有解释上补引 P0212 的修改，通过定点替换落实，没有为补引另写重复段落。这是有用的小能力。
2. **Ch5/U04 保住主要职责。** 新作者首轮已经写出方案差异、供体菌群与安全管理三组内容；baseline 首轮只有第一组，后来由已有补写补齐。新稿较紧凑，但最终两者都保留主要条件、供体案例和制剂安全讨论，不能仅凭首轮字数或补写次数选版。
3. **Ch1/U4 未改善跨章分工。** 新稿除了疗效和安全性数据，又展开微生物表位相似性、人源化小鼠等后章知识。背景不再重复的目标没有落实；没有新增独立任务，却扩大了本处展开。保留这些材料的价值，但本轮并未得到更清楚的篇章分工。
4. **Ch2/U03 的好机制保住了，跨章重复没有减少。** 两稿都讲清屏障状态、活菌与无细胞组分区别、CCR7/DC主动转运、髓系重编程及人鼠外推。新稿仍完整介绍65%不良事件、15%心肌炎和40天起病等后章案例数据，未显示值得默认加上下文的连贯性收益。
5. **Ch6/U3 显示出组织代价。** 新初稿从“除 FMT 外”起笔，仅写原第三项益生菌/用药任务，前两项FMT任务与表格没有写出。现有核查正确识别缺口，补写生成了对应内容；补写响应自己也记录：只能追加，导致先“除FMT外”、后追加FMT解释的顺序倒置。baseline 的首轮已经按FMT→供体条件→表→其他干预展开。缺项修回来不等于新上下文改善了阅读顺序，也不能把漏写造成的短稿当作去重成功。

我选择 baseline 的理由是全篇服务收益，而不是追究旧科学残余：候选在一处收敛了安全性预告，却在另一处扩大后章内容，并在关键重复单元引入任务遗漏与追加后的顺序问题；新增上下文还提高输入和费用。保留现版的知识展开和已有全文编辑更划算。

## 正式接入与验证

正常入口为 `run_review_harness.py --delivery-start body`，接受完整 `FULL_BODY_INPUT.json`，也可通过生产 manifest/packet/arrangement 导出当前输入。它复用原分单元作者、任务核查/一次补写、装配与全文编辑，输出实际选中的句柄稿、编号读者稿和引用目录；没有另造指南或正文生成器。

完整29单元的免费恢复验收已经走过相同产品运行库与原有工厂：原响应及采用稿不变，新增模型调用及预算预留均为0，实际选中已有全文编辑稿，编号目录187个论文身份。使用不存在的凭据文件验证未读取密钥。此项是完整正式接入的缓存验证，不冒充这轮重新生成七章。

现版已有全文编辑曾自主压缩第1/6章重复的临床数据并保留第5章主述，增加第3→4章具体衔接。其完整产物保持原样；本轮没有手写更好的段落、塞入科学答案或重写已认可稿件。

最终默认配置、受测/接入源码、运行命令、必要控制与费用以同目录 README、SOURCE_VERSIONS.json、COSTS.json 及 EVIDENCE.zip 中原始记录为准。对照采用稿和逐单元差异完整保留，允许云端直接复读。所有本轮真实作者/核查/补写都用 Plus，Max 为0。
