# 完整BODY实验的内容观察点

本文件是下一轮实验的监督方案，不代表各阶段已经完成真实验证。正文规划、编排、写作、装配是本轮范围；后置首尾模块不在其中。精确执行顺序与函数以同目录stage_audit/STAGE_MAP.md为准。

## 如何尽早区分问题

每个阶段同时看“它实际读到了什么”和“它实际做成了什么”。下列现象对应不同处理：

- 输入本身缺少对点材料：交给已有本地检索、补充或精读工具；不能指望换写法生成知识。
- 上一步已有内容，本步实际消息里没有：优先查投影、材料归并、身份定位或恢复接缝。
- 内容进入本步消息，但输出省略：属于任务分工、输出容量或模型采用问题；不能靠重跑更早的检索去修。
- 输出已经正确，下一步又改薄或写强：定位第一次发生变化的消费者，避免从全文结果倒猜。
- 只有少量措辞/归属误差：按用户认可的非阻塞工程容错记录；不自动追加模型调用。

## 逐阶段内容观察

| 阶段职责 | 运行时重点阅读 | 可用结果应具备什么 | 发现不足先比较什么 |
|---|---|---|---|
| 全局构思 | 原问题、材料主题信息、实际构思响应 | 有自己的组织视角，覆盖问题；入口型引言和最终总结退出BODY，必要背景/理论不被赶走 | 原问题与实际构思输入；输出是否被某个材料缺口支配 |
| 一级纲要 | 全文主张、章节知识问题、材料供给概况 | 每章有实质任务且互相推进；不是一组论文分类标签 | 构思响应与一级消息、一级响应 |
| 来源路由 | 实际候选列表、A/B认识及路由输出 | 案例、背景、比较材料有合适去处；跨章复用有不同作用 | 候选池与各章实际路由；不能只数分配篇数 |
| 章节提案与统筹 | 各章提案、章间解释责任 | 每章提出具体可展开的知识问题；全篇主线不会在局部主题中消失 | 独立提案与统筹后分工，哪些任务被删/合并以及理由 |
| 补充与定向精读 | 具体问题、实际材料、reader输出、工具反馈 | 对点增量可用，既有材料不丢；部分回答保留，不变成领域不存在研究的结论 | 工具任务→实际阅读输入→结果→负责人收到的材料 |
| 章节细化 | 真实材料与具体论述任务 | 有概念教学、机制展开、代表案例、比较条件和必要边界；来源不只是挂名 | 材料中丰富的信息与细纲展开，新增材料是否真有贡献 |
| 全局协调与负责人修订 | 综合意见、负责人实际消息、修订前后任务 | 反馈落进内容；有效任务和案例仍在；全文主张不是范围的替代字段 | 协调意见→负责人输入→更新后的段落/案例；缺在哪里首次出现 |
| 案例扩展与正式计划交接 | 候选真实认识、已选用途、正式packet | 代表研究成为有内容用途的素材；可用综述转述不强制自身A/B；未选理由合理 | 案例输出与正式packet，再看编排实际来源目录 |
| 章节编排 | 原任务、拆合引用、段落/表任务和实际材料目录 | 改顺序和拆合服务论证，原任务含义、条件、指标、来源关系不被重写抹平 | 负责人原brief→source_brief_details→最终writer消息 |
| 单元写作 | writer实际输入、正文与表格 | 多篇材料共同解释问题；条件/阴性结果有意义地保留；任务确实展开 | 已输入任务与实际段落；同一张实质比较表可承担多个任务 |
| 全文装配 | 各单元与装配正文、引用目录、未完成项 | 已写内容完整保留；引用身份正确；缺件/漏表不伪装为完整交付 | 单元正文→装配稿；这是交接检查，不是全文科学质量认证 |

## 建议的监督方式

在构思/一级、提案统筹、细纲与案例、编排、写作/装配五个自然边界做内容检查。无需每个请求后加一轮模型审核；保存程序已有的输入/响应/阶段产物即可，检查者读取实际文件。

每次检查记录一个简短结论：知识与任务有没有变丰富、哪些内容减弱、减弱最早出现在什么阶段、是否影响继续运行。不要把“程序ok”“来源数够”“全部字段齐”当作质量结论。

完整实验必须重新生成构思至正文；当前局部实验可以使用历史章节任务作为受控输入，两者不能混称。本地索引、论文、A/B卡、兼容的精读和补充可复用，旧PLAN/纲要/章节成功缓存不能作为新实验跳过待测阶段的理由。同一轮中断恢复则应复用兼容有效结果。
