# 首尾调研与全文校验员准备

本目录是2026-10-12的准备资料，**不是已接入生产或真实模型测试通过的新模块**。当前真实首尾样稿及源码背景先读[云端对齐入口](../serial-parts-live-20261011/CLOUD_READ_FIRST.md)。

## 需求与设计分开

用户决定先研究跨领域顶刊综述的引言/摘要/结语，再讨论首尾改造，特别要求引言重要主张有真实引用。用户另外提出独立全文校验员，以严格的旧片段/新片段JSON交给程序执行，替换失败反馈给模型修正，最多两轮。用户举出的缩写、公式、矛盾是检查示例，不代表这些缺陷全都存在。

本地Agent落实的是：真实稿件与现有程序盘点，归纳五类检查方向，写出通用提示词和替换反馈设计；没有人工执行替换，没有将当次科学答案写进通用提示词。当前源码`article_text_editor.py`已支持一次精确替换，但尚无这里设计的两轮失败反馈闭环。

- [云端研究任务完整提示词](CLOUD_RESEARCH_PROMPT.txt)：约30—40篇、跨至少6领域，重点是功能推进、引用与首尾分工，允许云端独立完善研究方法。
- [全文校验员通用提示词草案](FULL_MANUSCRIPT_CHECKER_PROMPT.txt)：术语缩写；数字/单位/统计/数学；结构/图表/引用；全文语境一致性；成稿表达及无效重复。
- [盘点证据及建议接缝](INVENTORY_AND_INTEGRATION.txt)：记录具体行号、稿件哈希、已确认与待核实事项。这里的案例只作评价数据，不作为生产模型必须发现的答案。

建议接线为首尾装配后→全文校验→最终编号→出版；复用现有解析和确定性替换。最多两轮按“首次全文检查＋一次失败反馈”解释；这是本地具体方案，用户和云端可依据实际收益调整。新的跨领域调研、校验员代码和真实测试均未开展。

原始稿件、BODY能力和历史结果保留。本次上传不新增项目付费调用。
