## 最小实现路线

### A. 显式已有论文应获得实际阅读机会

1. 接通请求已有的 `known_papers` 与 `known_paper_handles`。优先使用 paper_id / canonical_paper_id 及现有当前来源映射，查本地索引；不要只看一个可能属于旧run的P编号。
2. 请求明确指向且索引可解析的论文，不得因为FTS排在候选窗口之外而完全不读。将它的相关片段纳入本地阅读候选，并保留正常搜索结果。
3. 定点纳入只是“让判断器看到”，不是认定相关、不是强制引用、不是自动 fulfilled。没有可用片段、身份无法解析或内容不回答问题时，保留正常 partial / unmet / 外查分流。
4. 不要求全文重读、再次下载或重新生成A/B。复用索引、已有卡片、相关片段和可用阅读材料。综述转述的原始研究仍可使用转述内容加引用身份，不强迫再读原论文。

### B. 无显式已有论文时，允许一次有界的本地扩大

1. 正常首轮阅读保持原规模；仅当首轮未能满足需求且本地仍有未读候选时，允许一次本地扩展。
2. 扩展必须同时考虑论文覆盖和片段预算。优先让更多不同候选各有一个相关片段，避免同一两篇的多个片段占满全局窗口；必要的后续片段再按问题加入。
3. 可先以候选12篇、每篇首个相关片段、约24K字符的增量阅读预算作为实现起点；参数可调整，但必须有限，不能整池灌入、每轮翻倍或改成全文批读。这些数值不是质量达标标准。
4. 相同有效输入恢复时不得反复执行同一次扩展。新增问题、输出要求或材料按现有兼容契约处理；原有成功结果、partial内容和故障记录保留。
5. 如果使用已存在的查询改写，应检查改写后的方向有没有到达实际读取端。不要以“生成了新检索词”冒充“读到了新材料”。若打通这一点需要明显扩架构，先记录待办，本轮不造新调度层。

不必同时改所有列出的文件。以修复实际请求→候选→片段→模型输入的最短路径为准。保留原主线和03已通过的行为。
