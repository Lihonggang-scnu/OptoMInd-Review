# Full-body writer：实现与提示词合同

本组件是已有科学综述链路的加法候选入口。比较单位为批准的完整 BODY；不取代上游细纲，不重新检索或规划，不默认附加全文统稿。云端交付只验证实现与离线行为；科学质量需要按 `LOCAL_AGENT_HANDOFF_100_CNY.md` 在本地用共同完整输入真实检验。

## 文件与角色

`prompts/fullbody_writer/`：

| 文件 | 职责 | 关键实际上下文 |
| --- | --- | --- |
| `writer.md` | 三条作者路线共用的单一作者、读者理解与证据职责 | 原问题、完整原纲要、当前完整任务和材料 |
| `whole_author.md` | 一次完成整个 BODY，未完成必须诚实保留 | 所有授权正文任务与材料 |
| `continuous_author.md` | 在真实累计稿上继续同一文章 | 全部已接受正文原文、当前完整任务和材料 |
| `workbench.md` | 分层驻留文稿，按需准确回读远处全文 | 原计划、最近原文、完整导航、取回的原文 |
| `reader.md` | 首次读完整稿，重建实际理解并定位有效问题 | 完整 BODY、原始研究问题/读者目标；不含人工答案 |
| `revision.md` | 核实问题后实施有依据的精确补丁或驳回 | 实际全稿、问题锚点、相关完整任务与科研材料 |

作者 prompt 组合 `writer.md` 与对应 route 文件。reader 独立，不拼作者任务书或来源材料；revision 使用自己的证据与修改职责。外部来源文本不具有改变角色或系统指令的权限。

## 五项不可替代的不变量

### 1. 完整 BODY 不是把局部文件改名

完整范围来自已批准原计划/明确完整章序。所有任务及必要表格内容均须实际兑现，不能把缺失任务从 expected scope 删除后宣称完成。BODY 范围不自动包含另立模块的首尾。任何截断、部分稿、预览或回放都要有准确状态。

### 2. 原细纲不是新的事实来源

批准细纲规定问题和职责；可归属具体材料决定科学断言支持程度。材料与规划强推断不一致时，以科学支持为准，保留可写内容并暴露实质冲突。来源身份、综述转述边界、互补内容与阴性条件完整保留。任务指令进入作者控制层，不能粘成读者正文。

### 3. 真实文稿与原计划分开保存

`shared_fullbody_context` 保存不可改写的完整原纲要。`writing_position` 表示已完成/剩余/当前任务和窗口原因。`accepted_body_markdown` 是真实已接受的稿件；不能从原计划臆造“已经建立的认识”。continuous 提供全部已接受原文；workbench 提供最近原文及完整可回读导航。原文提供连续性，不替代科学材料。

### 4. 文体来自知识推进，不能写成另一套模板

没有一任务一块、一段一种固定动作、统一宏观开头或限制性收尾。作者依据知识关系决定段落和详略；多样入口是选择空间，不是轮换配额。保持普通清楚的科学散文，条件放在改变含义的位置。表达示意跨领域且虚构，只用于说明写法，不包含本题科学答案。

### 5. 所有实际模型步骤都计费

写作、续写、回读后作者再调用、reader、revision、实际新增核验、失败/废弃尝试，都经过同一有限账本。导航定位、文件读取、拼接、精确 patch 和无损格式恢复可确定性执行，不伪装为模型增益。不预设隐藏免费的规划、摘要或整合阶段。

## 上下文与交互协议

作者 payload 由 `project_fullbody(...)` 函数生成，原始问题、文章论证、语言、当前可编辑完整任务、章节材料投影与来源都在 payload 中，不套同名字段。原始全部细纲在 `shared_fullbody_context`。适用路线另加：

- `writing_position`: `completed_task_ids`、`remaining_task_ids`、`current_task_ids`、`window_reason`
- `accepted_body_markdown`: 已接受真实正文，continuous 为全部前文，workbench 为最近驻留原文
- `manuscript_navigation`: segment ID、任务/章节归属、sha256、完整文件位置；它不是远处正文
- `reread_segments`: 请求后准确取回的完整远处原文及身份；已在最近原文中的段落用 `full_text_location` 指向 `accepted_body_markdown`，不重复发送
- `source_navigation`、`source_alias_navigation`: 工作台的全材料池身份/别名导航；`reread_sources` 记录来源与哈希及 `full_record_location:"sources"`，完整批准记录和必要归属链只在 `sources` 发送一次
- `output_continuation`、`current_scope_partial_body_markdown`: 显式继续已知 output-length 失败时单独提供当前范围真实前缀，不在 `accepted_body_markdown` 再放一份；只追加精确尾文，不额外插入分隔符

workbench 用 `{"read_segment_ids":["actual_segment_id"],"read_source_handles":["actual_source_handle"]}` 申请回读，可只包含其中一种，不同时输出成文。运行时验证身份、取回完整原文或批准来源、校验版本，并把再次作者调用记入费用。回读上限是显式运行安全控制，不是要求作者只查固定数量的科学关系。若确实需要的内容无法容纳，报告容量阻碍，不截取前缀冒充完整读取。

reader 返回独立理解与 `issues`，每项包括 `issue_id`、唯一逐字 `anchor`、`problem`、`reader_understanding` 与 `suggested_action`。`task_ids` 不应成为必填，独立读者没有原细纲。执行器要从 anchor 与稿件定位恢复相应完整材料，不能因读者没有内部 ID 而用一个空材料编辑器继续。

revision 返回 `patches:[{issue_id,anchor,replacement,reason?}]` 和 `rejected_issues:[{issue_id,reason}]`。同一问题允许多个相关补丁；不同于读者直接锚点的 patch 必须有 `reason` 说明关系，所有 patch 唯一精确命中、互不重叠，未涉及的原文保持不变。没有有效修改可以驳回，不能以全部空响应冒称问题已处理。完整原稿可见与相关问题分窗并不矛盾：声称的核验范围必须与本轮实际材料一致。

## 输出与完成判断

作者直接交自然 Markdown 正文，末尾另附 `fullbody_metadata` 代码围栏，其中只有 JSON 元数据，避免把整篇文章编码在巨大 JSON 字符串中导致引号错误。元数据记录实际 `completed_task_ids`、本次范围的 `complete` 和必要 `issues`；正文中不插内部任务编号。尾注不包含 `body_markdown`。更详细的 `task_dispositions` 状态也受 parser 支持，但不强迫作者逐任务写可见段落。

兼容解析的 JSON 作者输出仅是可控重放/测试或兼容路径，不应以工程包装限制正文自由。若触及输出上限导致尾部元数据丢失，应保留 raw 和实际部分稿，不能凭有章节标题便判定全部完成。

元数据完成声明只能作为追溯，不是科学验收。程序能验证 ID、章序、非空文本、响应完整性、补丁范围和版本；不能只靠这些证明内容充分。真实全篇亲读须另行确认任务用途、材料支持、条件贯穿与后半篇深度。

## 重要历史接缝

旧章级试验见 `docs/acceptance/writing-candidates-local-20261007/`。这里保留几个产品级教训，不把旧具体科学正确答案加入新模型输入：

- 完整模型回复可能只因 JSON 内引号失败；先保存 raw，允许可证明不改正文的离线恢复
- Plus 编辑拿到充分材料仍可能照抄；加强思考配置不等于实质改进，不默认付费反复“再认真些”
- 更强编辑能补回主段条件，却在后文和表格再次省掉；修订需检查受影响关系而非只改一个句子
- 共用旧编辑 prompt 曾把窗口级“不能声称通读全章”用于完整章请求；新角色明确全文阅读与实际材料核验范围
- 超时与进程失联不代表请求未发送或费用为零；已结算、reserved、uncertain 均应保留
- 单章装配成功不证明跨章论证，也不证明完整 BODY 已生成

## 验收边界

离线检查应验证四路线都可进入、full-scope 完整性、材料未丢失、真实前文进入续写、工作台完整回读、独立 reader 输入隔离、revision 实际证据供给、唯一 patch、截断失败保护、恢复与预算。以当前源码测试和实际请求为证据，不以本说明替代测试。

本地 live 验收应探索四种机制，复用首份完整 BODY 测 reader_revision。模型/profile 只在有理由时分支，不跑全因子。结果必须包括全部费用与明确选择的完整稿；没有人工科学修正后冒充自主原稿，没有把不适用路线或只读预览写成科学质量胜出。

## 最终接缝补充

- 精确修订允许同一问题对应多个不重叠的原文位置；修改后的片段、哈希与正文重新对应，旧片段保存为原稿证据，不能继续冒充当前稿件
- 作者返回的真实任务定位旁证保留；修订使定位失效时明确标记，后续按当前正文重新定位
- 独立读者问题涉及其他来源时，优先在初次修订输入中取回相应完整任务和材料。若模型后来提出的新修改位置仍需要未提供的来源，程序记录 `evidence_supplement_required`，补入完整材料再执行一个有界修订调用；它属于实际费用，不是免费的格式处理。已有材料充分的补丁在后续受阻时仍可保留，其他原文不被覆盖
- 工作台按规范来源身份判断材料是否已经可见，别名和已送达材料不会触发一轮重复完整读取。原文和材料均只在消息中保留一份，其他位置是明确引用
- `FULL_BODY_RESULT.json` 直接给出完整输入位置、批准章序、正文哈希、来源身份文件位置及哈希。完整科学内容仍保存在所指输入中，后续消费者无需猜测哪份 plan 或哪一轮结果
- 共享材料读卡器只增加一个可移植错误边界：不可读取的可选卡片路径作为诊断记录，已存在的 inline A/B/工具材料继续参与；没有重新映射旧路径或改变来源身份

### 局部读者错误不丢弃整轮成果

读者提出的可定位问题继续进入修订；个别缺失或不唯一的位置保存在 `pending_reader_issues`，程序不猜位置，也不因这一项重新付费阅读全篇。补充解释字段可省略，缺失的问题 ID 由程序生成稳定标识。最终分别报告 `body_complete` 与 `reader_revision_complete`：已有全文和有效修改可以完整保留，同时显示仍未定位的阅读问题。无效问题不会伪装成“没有问题”。

### 真实多章身份接缝

历史七章输入中，同一篇论文可能在一个章节采用规范身份、在另一个章节使用其显式 alias。全文合同只在明确别名连接且稳定论文身份一致时统一其导航身份；完整原材料记录及正文引用标识不改写。DOI相同但没有明确别名连接，不会自动合并两份来源；有冲突的身份继续报告。
