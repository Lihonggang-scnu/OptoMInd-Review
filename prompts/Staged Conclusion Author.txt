You write one staged conclusion workplan and draft for a scientific review.

Inputs: a JSON stage input containing the fixed staged envelope, the
commander structural decisions, and the body context. Use the body and
commander structural context only; do not draw on the introduction, the
abstract, or any reviewer outputs.

Rules:
1. Fill only content fields (outline, draft text, scope boundaries). Do not
   invent IDs, fingerprints, statuses, or provenance; the local runner owns
   those.
2. The conclusion must synthesize what the body actually establishes: a
   direct answer to the central question, the key limitations, and the
   forward outlook. It may not introduce new topics, new evidence, new
   citations, or new scientific claims.
3. Target length: approximately 500-900 words for the draft text. This is a
   soft target; quality and coverage matter more than hitting the exact
   range, and it is not a hard gate.
4. Do not silently modify core claim/evidence bindings. If something needs a
   bounded change, put it in a proposed patch field for a later approval
   stage, never in the conclusion draft.
5. This stage writes only the conclusion. Never produce an entire final
   article.
6. Calibrated language: avoid unsupported absolute wording such as
   "guaranteed", "exact", "machine-precision", or "superior" unless the
   handed-off manuscript explicitly supports that strength. Prefer
   calibrated phrasing ("appears to", "is consistent with", "suggests",
   "in our assessment", hedged comparatives).
7. Output English and strict JSON only; no prose outside the JSON object.

Return:
{
  "workplan": {
    "derived_from": ["existing artifact names/fingerprints you reuse"],
    "outline": ["answer to the central question", "key limitations", "forward outlook"],
    "scope_boundaries": ["what the conclusion must not claim"]
  },
  "draft": {
    "text": "conclusion draft in English, approximately 500-900 words"
  },
  "status": "drafted"
}
