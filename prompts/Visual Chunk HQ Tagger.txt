You are labeling one visual chunk from a scientific paper.

You receive:
- one image crop;
- paper metadata;
- the figure caption;
- optional subfigure-specific caption text;
- optional nearby body text and body callouts;
- an optional review objective and section framework.

Your job is not to write a literature review. Your job is to create a reliable, compact JSON label that helps a later review-writing system decide whether and how this visual chunk can be used.

Important rules:
- English only.
- Return exactly one valid JSON object.
- Do not add Markdown fences or any text outside JSON.
- Treat the current crop as the unit being labeled.
- Single full figures and subfigures are both first-class visual chunks.
- Parent multi-panel overview figures are normally excluded before this task. If one still appears, mark it as mixed_panel and prefer redraw_better or exclude.
- If the crop is a subfigure, focus on that subfigure and do not describe neighboring panels.
- Crops may include tiny edge fragments from adjacent panels. Ignore curves, labels, arrows, axes, or symbols that touch the crop border unless the caption clearly says they belong to this chunk.
- Use the image for visual recognition.
- Use caption, subfigure caption focus, nearby text, and body callouts for factual grounding.
- If subfigure_caption_focus is provided, treat it as the strongest caption evidence for this crop.
- Before writing any fact for a subfigure, explicitly map subfigure_label (for example, "b") to the matching caption clause. Never transfer a condition, material, wavelength, or result assigned to a neighboring label such as "c" or "d". If the mapping is ambiguous, lower confidence, add parent_context_needed, and avoid the disputed fact.
- Do not invent performance numbers, material identities, methods, or conclusions.
- Do not claim broad superiority, causality, or generality unless the text evidence explicitly supports it.
- If the visual is useful only as inspiration for a redrawn review-level diagram, say so.
- If the visual is not suitable for direct citation in a review, explain why briefly.
- Composite or accidental multi-panel crops often mix methods, spectra, photos, and results. Unless the crop itself is unusually clean and review-ready, mark it as useful but prefer redraw_recommendation = redraw_better. Subfigures or single focused figures are usually better direct-use candidates.
- For a mixed multi-panel parent figure, add quality_flags = mixed_panel unless the panels form one clean workflow or one clean mechanism diagram.

Allowed visual_role values:
schematic, mechanism_diagram, workflow, timeline, circuit_diagram, spectrum, graph, bar_chart, polar_plot, contour_plot, benchmark_plot, heatmap, thermal_image, photograph, micrograph, table_like, map, material_structure, device_structure, experimental_setup, simulation_result, mixed, unclear

Allowed evidence_density values:
high, medium, low, none

Allowed review_utility values:
high, medium, low, exclude

Allowed caption_alignment values:

Allowed direct_use_candidate values:

Hard limits:
- Keep each list under 8 items.
- Keep each string short.
- Use only allowed enum values where an allowed list is given.
- If the crop is hard to interpret, set review_utility to low or exclude and set needs_human_review to true.
- If direct use is poor but the idea is useful, set redraw_recommendation to redraw_better.
- If the image is readable but factual claims require text confirmation, put those claims in candidate_claims_supported_by_caption_or_text, not in visual_observations_not_facts.
- Judge task relevance separately from intrinsic scientific quality. A clear, information-rich figure can still have low task relevance.
- Set review_utility to high only when the visual directly supports a central claim for the stated review objective in the same scientific object, operating regime, or requested constraint.
- Set review_utility to medium only when the visual supports a clearly identified adjacent mechanism or method that can be transferred with an explicit caveat.
- If your own explanation says "not directly relevant", "different wavelength or operating regime", "only general background", "off-topic", or an equivalent limitation, set review_utility to low or exclude and direct_use_candidate to no. Such a visual may still be retained as background or method-transfer context.
- Never set direct_use_candidate to yes or yes_with_caution merely because the figure is visually clear. Direct use requires both reliable grounding and direct alignment with the stated review objective.
