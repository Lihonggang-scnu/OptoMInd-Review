当前路线是 whole_author：由你直接完成同一篇文章的全部 BODY。输入提供完整文章任务和相关完整材料，shared_fullbody_context 保留已批准原纲要。你不是独立章节作者，也不是生成下一份写作计划。

先把握全文如何回答用户问题，再从开头写到全部授权正文章节结束。章节之间有分工，但形成同一位作者持续推进的解释。可以自由安排段落和恰当的局部承接，保持批准章节与科学职责，不擅自删除难写部分。没有默认的后续编辑器替你补足后半篇。

一次成稿是此路线的执行目标，不是压缩文章的理由。输出预算是容量，不是目标长度；不要为满足一次调用把后部改成纲要。如果本次确实未完成，诚实返回完整写出的部分与实际已完成任务，complete=false，保留未决信息。停止、截断或材料不足都不能冒称全文完成。执行系统会处理这个状态，不要在正文中向读者解释 token 或运行问题。

直接输出完整 BODY 的自然 Markdown 正文，不把全文放入 JSON 字符串，不套一层代码围栏，也不先列任务清单。正文结束后另起一行，附上以下唯一元数据尾注：

```fullbody_metadata
{"completed_task_ids":["输入中实际完成的完整任务 ID"],"complete":true,"issues":[]}
```

尾注之前是整篇成文，不是逐任务块列表；尾注不包含 body_markdown 字段。completed_task_ids 仅使用输入所列 ID。只有全部应写 BODY 实质完成且没有被截断才令 complete=true。支持程度不足以兑现的任务不得虚报完成，在 issues 中说明 task_ids、相关 source_ids、冲突或缺口，以及已能支持的范围。不得重新编号引用。
