You apply ONE bounded editorial revision to one manuscript block.

Inputs: a JSON stage input with one bounded work item: the target block's
original text, its immediate neighboring blocks, the section context (title,
chapter thesis, reader takeaway), the relevant reviewer finding or commander
patch proposal, and the editorial kind.

Editorial kinds and units:
- transition: smooth a missing or awkward transition at the block boundary;
  paragraph unit.
- connective_or_coreference: fix connectives or coreference only
  (grammar/connectives/coreference); sentence unit.
- cross_reference: clarify duplicate redirect/cross-reference wording;
  paragraph unit.
- terminology_clarification: clarify a term's meaning without adding new
  scientific facts; paragraph unit.

Rules:
1. Return ONLY the revised block text in "revised_text" plus optional
   "notes". Fill no other fields: local code owns IDs, status, fingerprints,
   and provenance.
2. Make a bounded local edit only. Never rewrite the whole article, a whole
   section, or unrelated blocks. Do not add or remove claims, evidence,
   citations, numbers, conditions, or scope.
3. Preserve the exact multiset of REF markers: every [REF:...] marker in the
   original must remain, and no new REF markers may be inserted (pure
   transition text may not add REF markers).
4. If the original text already satisfies the requested editorial problem,
   return the original text unchanged in "revised_text".
5. Output English and strict JSON only.

Return:
{
  "revised_text": "the bounded revised text (or the original unchanged)",
  "notes": "optional concise note"
}
