# OptoMind Review 2 — 本地 Agent 强制规则

本文件适用于本目录及全部子目录。开始工作前必须阅读根目录 `README.md`。

## 当前升级基线（2026-09-29冻结）

开始涉及升级链路的任务时，必须同时阅读 `docs/REVIEW_V2_FROZEN_BASELINE.md`。该文档记录用户最新冻结决定、唯一推荐实现、旧模式用途和已知限制；早期工单、顾问方案、历史快照不是当前可直接执行的待办。

- 继续在 `local-upgrade` 的当前升级实现上工作；显式启用现有 `--planning-revision`。本次冻结没有改变其默认关闭行为。
- 不得因发现默认旧模式、早期快照或旧提示词而另造一套平行链路，也不得从 `main` / 云端精简 `review-v2` 覆盖本地当前实现。
- 本轮“材料/案例修复”“内容交接/写作保持”已关闭。除非用户重新提出相关工作，不自动重跑旧工单、加提示词或花钱修已记录的样例问题。
- 冻结是阶段开发基线，不是科研内容零错误认证；不得把03内容部分通过改写为全部科学验收通过。

## 绝对禁止

1. **禁止推送 GitHub。** 不得执行 `git push`、`git push --force`、`git push --mirror` 或任何等价操作。
2. **禁止推送 GitHub。** 不得添加 GitHub remote，不得恢复或修改本地推送地址，不得删除 `.git/hooks/pre-push`。
3. **禁止推送 GitHub。** 不得使用 `gh repo`、`gh api`、GitHub REST/GraphQL API、浏览器或其他工具修改远端仓库、Pages、分支、发布、工作流和仓库设置。

云端比赛提交版和 GitHub Pages 是冻结资产。本工作区只允许本地修改、测试、提交和回滚。只有项目负责人在未来明确批准一次具体发布后，才允许单独制定解锁与发布方案；一般性的“继续”“修好”“完成”不构成发布授权。

## 工作区边界

- 唯一工作根是当前 `OptoMind-Review-2` 目录；不要扫描、合并、覆盖父目录中的其他项目或平行支线。
- 不得从 `OptoMind-Review-1`、云端仓库或历史运行目录自动覆盖本工作区。需要取文件时必须先逐项比较并说明理由。
- `api_keys/` 内为真实凭据。不得显示、复制到提示词、写入日志、提交、上传或以哈希之外的形式外传。正常诊断最多报告文件名、存在性、非空行数和掩码。
- 运行输出只写入相对目录 `outputs/`；数据库、全文和缓存只写入 `data/`、`database/`、`literature_workspace/` 或运行目录。
- 不得把历史题目的缓存、主题身份、章节账本、视觉审批结果或引用映射直接复用于新题目。

## 主线约束

- 正式入口是 `run_review_harness.py`。
- 普通综述主线使用 `--no-research-plan`；可选研究计划分支保持关闭，除非项目负责人明确改变产品范围。
- 昂贵的全局关系图默认关闭，不得擅自启用 `--phase3-llm-dag`。
- 不设置零散的小阶段预算；优先使用一个经授权的全局预算，并为质量优先的视觉阶段保留合理子预算。
- 真实 E2E 必须显式使用 `api_keys/qwen-api-key.txt`，不得把 mock 回退冒充真实运行。
- 未获得题面、预算和启动授权时，只能做离线检查、单元验证和 `--preflight-only`，不得发起付费 E2E。

## 修改与验证

- 保留证据身份、正文引用和 bibliography 三层语义；`final_text_only` 没有片段链路不是删除正常引用的理由。
- 风格治理必须保持审稿人与返修作者分离，且不得改变 claim、citation、evidence 或 scope。
- 达到 `max_iters` 时先检查最后有效候选和下游资产，不得直接删除章节或从头重跑。
- 修改前先建立可复现失败；修改后至少完成语法检查、入口导入、相关回归和一次不调用模型的预检。
- 不删除用户资产，不清空有效运行目录，不覆盖 checkpoint；恢复优先使用原运行目录。
- 每次本地提交只包含一个可解释主题；真实密钥、输出、缓存、数据库和 PDF 临时文件不得进入提交。
