# OptoMind：光学研究文献综述与出版流水线

[English README](README.md)

OptoMind-Review 是我们为参加“挑战杯·中国青年科技创新‘揭榜挂帅’擂台赛”阿里云榜题“基于国产开源大模型的 AI Scientist 的研发与应用”（题目编号：XH-202619）开发的参赛作品中的一部分。它的主要贡献是：从一段用户的综述需求，端到端交付完整英文PDF产物。

该赛题方向 1A 要求参赛团队面向《Science》提出的 125 个前沿科学问题，搭建能够完成“问题理解—知识整合—候选假设生成—证据梳理—研究计划输出—反馈修正”完整流程的 AI 应用。围绕这一目标，我们目前完成了其中面向科研文献理解、知识整合与证据梳理的一部分能力，并将其实现为一个垂直科研领域 Harness——OptoMind-Review。它能够将一条自然语言研究问题逐步处理为可追溯的研究材料，进一步完成文献检索与组织、章节级证据整理、带引用的内容生成、视觉资产构建，并最终产出高质量文献综述及出版文件，从而形成一条较完整的“研究问题 → 证据 → 综述 → 出版物”自动化流水线。

现阶段，我们主要在光学与电磁学领域对 OptoMind-Review 进行了测试和验证。系统的领域知识与任务指令主要通过 `\prompts` 目录下的 `.txt` 提示词文件进行配置，因此其整体 Harness 与工作流本身并不局限于光学领域。我们认为，通过针对不同学科修改相应 prompts，即可较低成本地将现有流程迁移至其他科学领域。

## 在线成果回放

无需下载源码或配置密钥，直接打开：

**<https://lihonggang-scnu.github.io/OptoMInd-Review/>**

云端页面以统一的十三阶段研究主线展示三次真实端到端运行，可切换题目、查看字数与引用规模、模型调用、运行时间和费用，以 10× 速度播放原始过程事件，并打开中英文 PDF、引用映射、质量报告、结构审计和出版源文件。回放只读取已经固化并脱敏的产物，不重新调用模型或文献服务。


## 它能做什么

主线流程包括：

1. 读取研究问题并确定主题、范围和章节任务；
2. 检索论文、获取开放全文并提取正文片段；
3. 建立中央材料缓存和主题范围内的知识库；
4. 按章节选择证据并形成“观点—片段—论文”的论点材料；
5. 生成章节初稿并进行章节资产增强；
6. 交接和统筹全文结构，补写标题、引言、摘要和结论；
7. 规划、检索、生成并挂载视觉资产；
8. 补全文献元数据，编译英文和中文 LaTeX/PDF 出版物。

## 三次完整测试的成果

我们已经围绕三个具有代表性的光学主题完成了三次完整的端到端验证：输入模拟用户提问，经过文献检索、证据整理、章节写作、全文编排和视觉资产处理，最终输出可阅读、可复核、低成本的英文文献综述 PDF。下面同时列出成果规模和实际运行投入，让读者可以直观看到系统完成了什么、用了多少计算资源。

| 主题 | 英文正文规模 | 章节数 | 参考文献条目 | 英文 PDF | 有效运行时间 | 模型调用 | Token 总量 | 运行成本 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 光学衍射神经网络 | 约 13,700 词 | 7 | 121 | 37 页 | 约 2 小时 7 分 | 240 次 | 约 824.2 万 | ¥5.39 |
| 超表面全息：从逆向设计、制造到动态显示与成像 | 约 12,900 词 | 7 | 108 | 36 页 | 约 1 小时 34 分 | 444 次 | 约 1,000.0 万 | ¥6.43 |
| 规模化光子计算：从可编程集成光子芯片到 AI 加速与光互连 | 约 16,200 词 | 8 | 124 | 44 页 | 约 1 小时 59 分 | 259 次 | 约 952.1 万 | ¥9.66 |

Token 合计约为 2,479.0 万输入、297.4 万输出；表中“模型调用”按实际发出的模型请求统计，包含章节审稿、返修和必要重试，不是工具调用数。运行时间采用有效运行时间口径。词数按最终英文成稿正文统计，页数为英文 PDF 总页数，参考文献条目按最终书目统计。

模型调用使用 Qwen 系列的文本、视觉和图像能力，实际涉及 `qwen3.7-flash`、`qwen3.5-plus`、，以及第三次测试中用于概念图生成的 `qwen-image-2.0-pro`：文本调用覆盖问题理解、证据组织、论证、章节写作、摘要与结论、翻译和润色；视觉调用负责素材理解与审阅；图像调用负责概念图生成。三次测试合计包含 13 次视觉审阅、8 次图示方案生成和 6 次概念图生成，最终挂载 5 张生成图；这些是上表 943 次总模型调用中的视觉子任务。章节风格治理采用“审稿—返修”双角色，三次合计 44 次调用（22 次审稿、22 次返修），重点处理段落开头和术语简称的一致性。值得注意的是，截至本项目发布时，Qwen 已推出能力更强的新一代模型，例如 2.4 万亿参数 MoE 旗舰模型 Qwen 3.8 Max。我们预计，接入更强的 Qwen 模型能够进一步提升最终产出的质量。当前系统仍主要使用 `qwen3.7-flash`、`qwen3.5-plus` 等相对次优模型，主要基于两点考虑：第一，我们希望在尽可能低的成本下获得足够高质量的结果。目前 3 篇测试任务累计消耗约 2,479.0 万输入 Token 和 297.4 万输出 Token，实际成本仅为 ¥21.47；若全部切换至 Qwen 3.8 Max，按当前调用规模估算，成本可能上升至大约 ¥400。第二，我们也在有意测试系统本身的能力边界，即通过 Harness 内部的任务拆解、检索、证据组织、交叉校验和反馈修正等机制，尽可能降低系统对顶级基础模型能力的依赖。换言之，如果在次优模型条件下，系统仍能稳定产出质量合格的结果，就说明 Harness 本身具备较强的增益能力；在此基础上进一步升级底层模型，则有望获得更高质量的产出。


三次验证均覆盖规划章节，并完成了英文出版物的生成与基础出版检查。对应的最终出版物和静态回放见 [`artifacts/e2e/`](artifacts/e2e/) 与 [`replay/`](replay/)。


## 快速开始

需要 Python 3.11 或更高版本。Windows 用户解压源码后直接双击仓库根目录的 `START_OPTOMIND.cmd`；Linux 或 macOS 用户运行：

```bash
./start_optomind.sh
```

浏览器会打开本地统一前端：成果回放立即可用；“真实提问”会先检查项目资产、密钥、Python 环境、Qwen 和学术文献服务。首次真实测试缺少依赖时，入口会自动创建 `.venv` 并安装，不要求评委手工输入一串环境命令。全部检查通过后，问题输入框才会解锁。若希望完整模式生成 PDF，建议安装包含 `xelatex` 和 `latexmk` 的 TeX 环境；没有 TeX 时可使用快速真实验证模式检查“问题理解—检索—证据—论证—成稿”主链。

## API key 的放置方式

公开发布版本保留 `api_keys/` 文件夹和已经准备好的文件名模板，不包含任何真实密钥。使用者只需要把自己的凭据填写进这些已有文件，不需要重新创建或命名 `.txt` 文件：

```text
OptoMind-Review/
├─ api_keys/
│  ├─ qwen-api-key.txt
│  ├─ semantic-scholar-api-key.txt
│  ├─ openalex.txt
│  ├─ core_api.txt
│  └─ Unpaywall.txt
└─ ...
```

运行时会按相对于仓库根目录的路径自动发现 `api_keys/`。
其中：
- `qwen-api-key.txt` 用于 Qwen/DashScope 的文本、视觉和图像调用，是实时模型运行所需的主要凭据；每行可以放一个 key，运行时会把它们视为共享池并轮换使用；
- `semantic-scholar-api-key.txt`、`openalex.txt`、`core_api.txt` 和 `Unpaywall.txt` 是可选凭据，缺少时会使用公开接口或本地回退路径；


## 运行一篇新的综述

项目的标准入口是 `run_review_harness.py`。例如：

```powershell
.\.venv\Scripts\python.exe run_review_harness.py `
  --question "写一篇关于规模化光子计算的文献综述，阐述从可编程集成光子芯片到 AI 加速与光互连" `
  --execution-profile private_study `
  --no-research-plan `
  --auto-confirm-query-plan `
  --output-root outputs/research_harness_e2e
```

继续已有运行时，可以通过 `--run-dir` 指向既有断点目录。运行前可用下面的命令检查帮助和本地测试：

```powershell
.\.venv\Scripts\python.exe run_review_harness.py --help
.\.venv\Scripts\python.exe -m pytest -q
```

默认关闭昂贵的跨章节全局 DAG，但中央材料缓存、证据绑定和章节就绪检查仍然开启。如确实需要更长的全局关系推理，可以显式添加 `--phase3-llm-dag`，但是这会让运行时间变成数十个小时。

## 静态回放

仓库包含三次正式 E2E 运行的只读回放。在线版本见 <https://lihonggang-scnu.github.io/OptoMInd-Review/>；下载后双击 `START_OPTOMIND.cmd` 也会打开同一套界面。三次运行的最终公开出版物位于 `artifacts/e2e/`，精简事件记录位于 `replay/`。原始运行树、下载论文全文、运行缓存和真实密钥不包含在公开回放中。
